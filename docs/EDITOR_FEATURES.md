# BIRD 关卡编辑器 — 功能文档

> 独立 Godot 4.7.2 工程（`D:\Game\BIRD\Level Editor`），入口场景 `src/editor.tscn`，主脚本 `src/app.gd`。
> 编辑器本身不依赖游戏工程资源，只读取游戏项目里的 `editor/editor_manifest.json` 与地图 JSON。

---


设计原则：**清单驱动**。图层、瓦片调色板、实体类型、字段定义、数值模板、试玩命令全部来自清单；编辑器只负责编辑数据，不硬编码游戏内容。

界面全部由代码构建（无 `.tscn` 布局文件），样式只在 `ui_theme.gd` 里定义，`ui_kit.gd` 只做结构与语义组合，各面板不得写死色值。

架构模式：`app.gd` 与 `editor_canvas.gd` 是两个**宿主**，只保留引导代码（`_ready` / 快捷键 / 调色板入口委托）与一层**同名薄包装**（转发到控制器）；功能实现拆在 `RefCounted` 控制器里，宿主在 `_ready` 时 `preload(...).new(self)` 装配，控制器经 `app.` / `cvs.` 别名访问宿主状态。外部调用点（含测试）一律走宿主同名包装器，拆分对调用方透明。新增功能优先做成控制器，宿主只加一行装配与包装。

## 1.1 快速上手（使用方法）

**启动**：用 Godot 4.7.2 打开本工程（主场景 `src/editor.tscn`）直接 F5；或命令行 `godot --path "D:\Game\BIRD\Level Editor"`。

**首次启动**：选择游戏项目文件夹（内含 `editor/editor_manifest.json` 与 `maps/`）；下次启动自动加载上次项目（存 `user://settings.cfg`）；清单读取失败会在选择页给出错误说明。

**基本流程**：新建/打开地图 → 顶栏选图层（地形/装饰/实体/碰撞）→ 左栏选瓦片或实体 → 左键涂刷、右键擦除、矩形填充 → 切到实体层用「属性」工具框选、拖动、改属性 → `Ctrl+S` 保存 → 顶栏「▶试玩」在游戏里跑当前图。

**快捷键速查**：见 §10；**界面总览**：见 §10.1。

## 2. 项目接入

| 功能 | 说明 |
|---|---|
| 选择项目文件夹 | 启动时若无上次记录，显示选择页，`FileDialog` 选目录 |
| 清单校验 | 读取 `<项目>/editor/editor_manifest.json`，缺失/解析失败/无法读取均给出错误页 |
| 记住上次项目 | 写入 `user://settings.cfg`，下次启动自动加载 |
| 项目信息展示 | 顶栏显示 `projectName` |

清单读取后自动推导：`_maps_dir`（`<项目>/maps`）、每个瓦片的 `atlas_abs`。实体的画布占位框可在清单中指定 `editorSize: [宽, 高]`；未指定时可配置 `prefab` 路径，由编辑器从 prefab 的矩形、圆形或胶囊碰撞形状读取尺寸。

**图层/图集支持面（F5，批次 12）**：图层目前支持清单 layers 声明的 `terrain` / `decor`（tiles 型）+ `collision`（grid 型）+ 实体层——id 保留名固定，校验会拒绝其他 id；**多图集已支持**（tiles[] 多条目，索引 = source_id）。palette 分组、bgGroups、items 均走清单声明。

## 3. 地图管理

| 功能 | 说明 |
|---|---|
| 新建 | 填名字 → 120×56 空图，出生点 (2,2) |
| 打开 | 文件对话框，默认定位到 maps 目录，仅显示 `*.json` |
| 保存 | `Ctrl+S` 或按钮；写 `<项目>/maps/<名>.json`（制表符缩进 JSON；**原子写盘**：先写 .tmp 再改名，防写坏文件） |
| 另存为（改名保存） | 直接改名字框再保存，写到新文件；旧文件保留 |
| **改名自动迁移** | 改名保存时扫描全部地图，把所有 `target_map` 指向旧名的出口改到新名，状态栏报告迁移处数；迁移失败的地图会列出 |
| 改名防覆盖 | 改名的目标名已存在时拒绝保存，不静默覆盖别人的地图 |
| **未保存拦截** | 新建 / 打开 / 从地图列表切图 / 关窗口 时若有未保存修改，弹确认框；取消则中止操作 |
| **自动草稿** | 有未保存修改且距上次保存超过 2 分钟，自动写 `<名>.autosave.json` |
| **地图尺寸** | 顶栏「尺寸」改 `meta.w/h`（8–4000 格）；裁剪只改边界，不删已画内容 |
| **地图列表** | 右侧面板「地图」页签列出所有地图（名称/尺寸/实体数 + **缩略图**），当前图带 ▶ 标记，单击打开；**比正式文件新的自动草稿会置顶标出（〔草稿〕前缀），单击直接打开草稿** |
| **导出** | 顶栏「导出」：PNG 预览图（1–16 px/格）与统计文本，写到 `<项目>/editor/exports`；**「导出全部地图」一键批量出全部图的 PNG+统计**（批量精度上限 4px/格） |
| 地图名校验 | 拒绝 `/ \ : * ? " < > \|`、`..`、点开头、`con/prn/aux/nul` 等；校验后的路径必须仍在 maps 目录内 |
| 新建重名检查 | 同名文件已存在时拒绝新建，提示改用「打开」 |
| 读取容错 | 文件句柄为空、JSON 非字典时给出状态栏错误，不崩溃 |
| 格式版本 | 地图 JSON 带 `version`（当前 2）；读取老图自动升级（坐标取整），保存时写回新版本 |

地图 JSON 结构（与游戏侧 `MapLoader` 同构）：

```json
{
  "version": 2,
  "meta": { "name": "level_1", "w": 120, "h": 56 },
  "spawn": [2, 2],
  "terrain": [[x, y, atlas_x, atlas_y]],
  "decor":   [[x, y, atlas_x, atlas_y]],
  "collision": [[x, y]],
  "entities": [
	{ "scene": "crawler", "id": "e_1", "x": 10, "y": 8, "flip_h": false, "props": { "stats": { "hp": 7 } } }
  ]
}
```

## 4. 地形与碰撞编辑

| 功能 | 说明 |
|---|---|
| 图层 | 完全按清单 `layers` 生成；`tiles` 型为地形/装饰，`grid` 型为碰撞 |
| 瓦片调色板 | **两级导航**：先列类别再进资产。类别名优先取 palette 条目的 `cat` 字段，无 `cat` 用图集条目名（一个图集 = 一个默认类别），都没有 → 「未分类」；类别行显示「▶ 类别名（数量）」，点类别进入该类资产，首行「← 返回类别」回上级；40×40 缩略预览；清单没给 `palette` 时退回图集逐格铺满 |
| 涂刷 | 左键单格/拖拽连续；笔刷 1×1/2×2/3×3/4×4/6×6 |
| 擦除 | 工具擦除 + 右键快捷擦除（拖动连续） |
| 矩形填充 | 拖拽出矩形一次填满 |
| 碰撞层 | 选碰撞层后涂刷写入隐形碰撞块；红色半透明叠加显示，可开关 |
| **图层可见/锁定** | 顶栏 👁 隐藏当前图层（仅影响显示），🔒 锁定当前图层（涂/擦/盖/移等写入入口均有锁守卫） |
| 地形/装饰分层 | 装饰层独立 TileMapLayer，与地形同 z 层、树序在后 |
| 网格 | 按 `meta.w/h` 绘制；可开关 |
| 隐藏格 | `INVISIBLE_CELL = (4,0)` 作为碰撞占位格，调色板中自动跳过 |
| 旧格式兼容 | 地图无 `collision` 键时，用 `terrain` 兜底生成碰撞 |

## 5. 实体编辑

| 功能 | 说明 |
|---|---|
| 实体调色板 | 清单 `entities` + `thumb` 预览图；无缩略图的实体不进列表；单列横排图标+名称，长名不被截断 |
| 盖章放置 | 选中实体后在实体层点击放置，位置吸附格中心 |
| 实体 id | 自动分配 `e_N`；载入时继承原 id 并更新计数器，保证引用稳定 |
| 单选 | 「属性」工具点实体 → 选中并弹出属性面板 |
| 框选 | 实体层空白处拖拽框选多个；框选后画出外接框并提示「N 个实体 · 拖动可整体移动」 |
| **拖拽移动** | 属性工具按住实体拖动，松手吸附格点；按住框选集合中的成员、或在框内空白处按下，都整组一起移动；一次拖拽 = 一个撤销步 |
| **对齐 / 分布** | 顶栏「对齐」或 `Ctrl+L`：左/水平居中/右、顶/垂直居中/底对齐，水平/垂直等距分布；结果吸附格点，一个撤销步 |
| **朝向翻转** | `F` 键或属性面板「翻转」按钮：toggle 单个或框选集合的 `flip_h`，一个撤销步；数据写入地图 JSON `entities[].flip_h`，游戏侧应用到实体精灵 |
| **批量属性编辑** | 框选多个同类型实体后，属性面板出现「批量编辑同类实体…」：勾选要改的数值（stats）或普通文本字段统一写入；只影响选中里同 `scene` 的实体，引用字段不参与批量，避免破坏配对 |
| 删除 | `Del` 删除单选或框选集合 |
| 复制粘贴 | `Ctrl+C` / `Ctrl+V`，相对布局保持，粘贴到光标处并吸附格点；属性深拷贝，副本互不影响 |
| **剪切** | `Ctrl+X` 或顶栏「剪切」：复制进剪贴板同时删除选区，整件事算**一个**撤销步（实体层剪实体，瓦片/碰撞层剪框选区域三层+实体） |
| **实体大纲** | 右侧面板「实体」页签：列出 id/名称/格坐标，可按 id 或名称搜索、按类型筛选、**单击即定位**（无需双击）、悬停时画布上对应实体高亮、多选批量删除 |
| **实体碰撞占位框** | 有 `editorSize` 或可解析 prefab 碰撞形状的实体，在画布显示青色尺寸框和中心线；不改变地图数据 |

## 5.3 关卡清单（两种游戏形态）

`<项目>/editor/levels.json` 描述关卡组织方式，支持两类游戏：

| 模式 | 用途 | 清单作用 |
|---|---|---|
| `metroidvania`（大地图/银河城） | 地图互相连通，一个世界 | 用 `area` 分组，`start` 定新游戏入口；跨图靠 exit/portal |
| `level_select`（选关） | 线性关卡，逐关解锁 | 用 `order` 定顺序，`unlock` 定前置关；不需要跨图传送 |

清单结构：

```json
{
  "mode": "metroidvania",
  "start": "level1",
  "levels": [
	{ "map": "level1", "name": "苔原入口", "order": 1, "area": "tundra", "unlock": "", "secret": false }
  ]
}
```

编辑器「关卡」页签可直接改模式、起始关、排序（上移/下移）、区域名，并保存；「从地图生成」会按现有地图文件重建一份建议清单。保存时会自动剔除指向已不存在地图的条目。

校验会一并检查：清单指向不存在的地图、条目重复、起始关无效、解锁前置不存在、地图存在但未加入清单。

## 5.4 地形自动生成碰撞（辅助功能）

手动摆放碰撞仍是首选方式；顶栏「生成碰撞」提供批量辅助：

| 策略 | 行为 |
|---|---|
| 全部地形格 | 每个有地形的格子都生成碰撞（整块实心） |
| 仅顶部表面 | 只给「上方无地形」的格子生成（可站立表面） |
| 仅外轮廓 | 只给四邻有不空位的格子生成（贴边一圈） |

- 面板实时显示「将新增 N 格碰撞」预览。
- 可选「先清空现有碰撞再生成」。
- 只写碰撞层，不改地形；整体一个撤销步。
- 碰撞层被锁定时拒绝执行。

## 5.2 引用完整性校验

跨全部地图检查（`map_validate.gd`）：

| 检查项 | 级别 |
|---|---|
| `portal.target_point` 指向同图不存在的实体 | 错误 |
| portal ↔ portal 不成对（对方没指回来） | 错误 |
| 同一个 portal 被多个门引用（一对多） | 错误 |
| `exit.target_map` 指向不存在的地图 | 错误 |
| `exit` 选了目标地图但没选落点 | 错误 |
| `exit.target_point` 在目标地图找不到 | 错误 |
| exit ↔ exit 单向（对方没指回来） | 错误 |
| 跨图出口没有配置目标地图 | 警告 |
| `spawn_point` 没有被任何门/出口使用 | 警告 |

## 6. 实体属性面板

选中实体后，左侧面板按清单 `fields` + `stats` 动态生成：

| 字段类型 | 控件 |
|---|---|
| `entity_ref` | 弹出候选列表；候选按 `of` 过滤；已配对的 portal 标记「已配对」并禁选；悬停候选时画布黄框闪烁 + 连线 |
| `map_ref` | 下拉列出 maps 目录其他地图（排除当前图）；改图时清空旧落点并解绑旧对端 |
| `string`（普通） | 行内 `LineEdit`，即时写回实体 metadata 并标脏 |
| 落点 companion 字段 | 只读展示，只能用「在图上选落点」修改 |
| `stats` | 每项 `SpinBox`，标签区分「继承 / 覆盖」，`↺` 单键恢复继承 |
| 触发区专属 | 见下方 6.1，`scope` 为 `trigger_zone` 时追加 |

数值语义：实体 `props.stats` 只存**覆盖值**；未覆盖时使用资产模板默认值。

### 6.1 触发区属性

`trigger_zone` 是编辑器**内置种类**（`src/content/builtin_kinds.gd`），游戏工程清单不需要声明：

- 加载时 `manifest.load_from` 把内置种类合并进清单，保存清单时 `strip_from` 剥离，不会写回 `editor_manifest.json`。
- 没有 `thumb` 也**必须出现在实体调色板里**（`palette_panel.fill_entities` 对内置种类跳过无图过滤），
  盖章前在画布上按默认 2×2 画矩形幽灵。
- 尺寸来自**实例** `props.w` / `props.h`（单位：格），不是种类级 `editorSize`；矩形语义是 `[x, x+w) × [y, y+h)`，
  画布上 sprite 位置是矩形中心，`trigger_zone_origin()` 换算回左上角格坐标。
- 属性面板「触发区」区：尺寸（宽/高 SpinBox，改尺寸保持左上角不动）、触发方式
  （`enter` / `interact` / `auto`）、绑定事件（从 `content/events` 选，为空时提供「去内容库…」）、
  「只触发一次」、前置 `flag`。
- 画布绘制：半透明矩形 + 标签 `事件id · 触发方式 · 一次`；**未绑定事件**时用橙色并显示「(未绑定事件)」，绑定后为蓝色。
- 撤销/快照：`w/h/mode/event/once/require_flag` 不在清单 `fields` 里，
  `undo_history.TRIGGER_PROP_KEYS` 显式放行，否则保存会静默丢字段。

游戏侧契约（Area2D 实例化、`w×tileSize` 的 RectangleShape2D）见 `docs/content-development-standard.md` §5.3。

## 7. 传送系统

### 7.1 同图传送门

- `portal.target_point` 是 `entity_ref`，候选 `spawn_point` 与 `portal`。
- portal ↔ portal：双向互指一对一；重新配对时清理旧伙伴的反向引用，也会把「被抢走伙伴」的另一端解绑，避免一对多。
- portal → spawn_point：单向；一个落点可被多个门共享。

### 7.2 跨图出口

- `exit` 使用 `target_map`（地图名）+ `target_point`（目标图实体 id）。
- 「在图上选落点…」打开目标地图缩略图弹窗：
  - 点已有 `spawn_point` → 复用（同图与跨图共用落点）
  - 点另一张图的 `exit` → 双向配对
  - 点空白格 → 在该图新建 `spawn_point`（id 取该图最大编号 +1）
  - 点其他实体 → 拒绝并提示
  - 非 `exit` 实体不能与 `exit` 配对
- 配对规划由 `cross_map.gd` 一次算全：目标出口若原先连着第三张图，会把「解绑对端」一并列入计划，再统一落盘；写目标图失败则整条操作中止。
- 当前已加载地图不会被自动写盘（防止磁盘旧内容覆盖未保存修改），落点字段变更等用户保存时生效。

### 7.3 画布可视化

- 同图引用连线（黄）、跨图引用连线（蓝紫）。
- 目标闪烁高亮：展开候选下拉、悬停候选、选中目标时黄框呼吸。

## 7.5 背景图组（视差背景）

HK/Ori 式背景 = **N 张完整横条图 × 不同跟随系数**（视差），与画布尺寸/瓦片网格完全解耦（层开横向平铺后自动无限延伸，跟地图大小无关）。

数据结构（存编辑器清单，每图只存引用）：

```json
"bgGroups": {
  "tundra": { "layers": [
	{ "img": "bgs/tundra_far.png", "scale": [0.2, 0.05], "z": -20, "tint": [0.55, 0.6, 0.75], "alpha": 1.0, "mirror": true }
  ] }
}
```

- 地图 JSON 只存 `"bgGroup": "tundra"`；未配置 = 保持原渐变兜底（行为不变）。
- 层字段：`img` 相对游戏项目根；`scale` 跟随系数（远景 0.15~0.35、中景 0.5~0.7、前景可 >1）；`z` 排序（默认 -8，地形 0，负值都在地形后面）；`tint`/`alpha` 做大气透视（越远越暗、越接近天空色）；`mirror` = 横向无缝平铺。
- **图组 = 清单预设**：在 `editor/editor_manifest.json` 的 `bgGroups` 里手工定义（与瓦片件套同一工作流：改清单文件 → 重启编辑器/重载项目生效）；编辑器弹窗**只做引用选择 + 组内容只读预览**，不做新建/编辑。
- **游戏侧**：map_loader 读 `res://editor/editor_manifest.json` 的 bgGroups，每层一个 Parallax2D（`scroll_scale` + `repeat_size` 横向平铺）。
- **编辑器**：顶栏「背景组」弹窗选引用；画布预览带**视差模拟**（随相机平移按系数移动）；状态栏「背景」开关控制预览显隐；extract 保留 bgGroup（regress T-13 回归）。
- AI 出图：透明背景 PNG、2048×512 像素风横条、**每层分开生成**；无需 16px 对齐；逻辑分辨率 640×360 + 整数缩放，1080p/2K/4K 免费锐利放大。

## 8.5 内容库界面

顶栏「内容库」进入，与关卡编辑器、实体资产**平级**。数据落在游戏工程的
`<项目>/content/{dialogues,events,shops,defs,schema}/`，格式见
`docs/content-development-standard.md`。

**定位：实例为主、库为辅。** 日常编写走实体属性面板的「内容抽屉」（见 8.6），
全屏内容库用于浏览全部资源、批量整理、重命名与删除、跨图复用。
两者读写同一批 JSON，任一处改动另一处立刻可见。

界面结构：顶栏（新建 / 返回）→ 种类页签（对话·事件·商店·定义）→
左侧资源列表 + 右侧编辑区 + 底部校验条。切换页签自动选中第一项；
「新建」按种类生成可用模板（对话自带 `n1` 起始节点，模板在 `src/content/content_templates.gd` 共用）。

| 页签 | 编辑内容 |
|---|---|
| 对话 | 起始节点、说话者表（名称/立绘）、节点卡片：id / 说话者 / 文本 / 下一节点 / 终止 / 选项（文本+目标+动作）；节点与选项可增删 |
| 事件 | `once` 开关、步骤列表；动作类型与参数控件全部由 `schema/actions.json` 驱动（bool→开关、数值→SpinBox、引用类型→资源下拉、其余→文本框） |
| 商店 | 货币、条目行（物品下拉/手填 id、价格、库存 `-1`=无限） |
| 定义 | 名称、种类（取自清单 `entities`）、prefab/thumb、组件引用（对话/商店/互动事件）；「编辑」直接跳到被引用的资源 |

编辑策略：**改内存 → 写盘 → 就地校验**。文本类字段在失焦/回车时提交（不每击键写盘），
增删条目立即落盘并重渲染。校验问题以「错误/警告 + 字段 + 说明」行显示在编辑区下方，
结构沿用 `map_validate` 的 issue 形状，可直接并入既有问题面板。

未建模组件（如 `enemy_profile`）只保留键并提示，不提供编辑入口。

资源 id 一行右侧有「重命名」「删除」：
- **重命名**：`ContentStore.rename` 复制到新 id 后删旧文件，任一步失败回滚为原状。
- **删除**：先 `ContentStore.find_references` 扫全部种类，把「还有谁引用它」列进确认框再删；
  没有引用时直接提示可安全删除。删除后遗留的引用会变成悬空引用，由校验页报错。
- 面向作者的操作流程见 `docs/content-authoring.md`。

## 8.6 内容抽屉（实例为主的内容入口）

`src/ui/content_dock.gd`。停靠在画布与侧栏之间，默认收起，**不遮挡地图**——
这是"先摆实体、再配内容"的主路径。全屏内容库替代不了它：那个视图会把地图整个藏掉。

打开方式：选中实体 → 属性面板「定义」区 → 未配置时 **＋ 为此实体创建内容组**，
已配置时 **编辑内容（对话/事件/商店）**。

内容组就是 `defs` 资源，创建时自动生成 `grp.<地图名>.<实体id>`：

| 槽位 | 种类 | 说明 |
|---|---|---|
| 对话 | `dialogues` | 一段可推进台词 |
| 互动事件 | `events` | 优先级最高的互动（先演出再开店就走这里） |
| 商店 | `shops` | 商品表 |

每个槽位是**有序条目数组**，可以挂多份内容：

```
dialogue: [
  {"id": "grp.x.e_7.dialogue", "once": true},        ← 初遇，播完作废
  {"id": "dlg.idle",           "when": "met_smith"}, ← 认识之后才有
  {"id": "dlg.default"}                              ← 兜底循环
]
```

| 操作 | 说明 |
|---|---|
| **+ 条目** | 新建一份（id 带实例归属）或从库里追加已有资源 |
| **↑ ↓** | 调整顺序；**顺序即匹配优先级**，没有额外的 priority 字段 |
| **播完不再出现** | 该条 `once: true`，播完写 `<组id>.<组件>.<资源id>.done` 后跳过 |
| **前置 flag** | 该条 `when`，flag 为假时跳过 |
| **×** | 只从内容组移除引用，**不删资源文件** |
| **编辑** | 就地渲染编辑器，地图与实体保持可见 |

匹配规则：**从上往下，第一条「条件满足且没播过」的胜出**；全部不命中 = 该槽位当前没内容。
只放一条时行为与旧版一致。旧写法 `"dialogue": {"id": "x"}` 仍然合法，等价于单元素数组
（`DefModel.items_of` 归一化）。

**播放语义（一次性 / 可重复）** 是内容属性，写在条目上，不是资源生命周期：

```json
"dialogue": [{"id": "grp.map1.e_7.dialogue", "once": true}]
```

勾「播完不再出现」= `once: true`；取消勾选即恢复重复播放。**两种情况文件都保留**——
删文件会让引用悬空，而"不再说这段"只是不再触发，资源随时可改回来。

抽屉与全屏内容库共用 `src/ui/content_editors/*` 四个控制器：它们只依赖宿主接口
（`body / data / id / kind / manifest / commit() / rebuild() / schema() / open_kind()`），
所以同一套编辑器能同时跑在全屏视图和抽屉里，不存在两份实现。

- **状态栏分区**：操作消息与常驻指示（工具/坐标/脏标记）分列，互不覆盖。
- **弹窗**统一走 `_open_popup()`：按内容最小尺寸居中开窗并夹回可视区，关闭即释放节点。内容宽度固定为 `POPUP_BODY_W`，换行标签必须显式给宽度——否则 Label 在宽度未定时会被测成接近 0 宽、高度爆成几十行，把弹窗撑到一整屏。
- **空状态**：未打开地图时画布中央给引导；地图列表、实体大纲、属性面板为空时都显示图标 + 主文案 + 下一步提示，不留纯空白。

- 鼠标滚轮缩放（0.5×–6×），中键平移。
- 网格 / 碰撞显示开关；图层可见（👁）与锁定（🔒）开关。
- 状态栏：当前地图名、笔刷尺寸、当前工具、光标格坐标、操作提示。
- 游玩视野预览：鼠标处与出生点各画一个 640×360 框。
- 撤销栈上限 80 步，快照以 JSON 字符串保存（比嵌套字典省内存，深拷贝天然隔离）。
- 区域复制粘贴：瓦片层框选 → `Ctrl+C` 捕获地形/装饰/碰撞**与区域内实体** → `Ctrl+V` 幽灵预览（含实体幽灵）→ 左键落位。

- 未打开地图时禁用全部编辑交互（防呆）。
- 未保存修改时新建/打开/切图/关窗口都会先确认；超过 2 分钟未保存自动落草稿。

## 12. 已知边界

- 改名迁移只改 `target_map`；若其他地图的 `spawn`/瓦片数据里嵌了旧名文本，不会被改。
- 自动草稿是整图覆盖写，不做多版本历史；草稿文件不会自动载入，需手动打开。
- 撤销快照为整图快照，大图（数千格 + 数百实体）连续操作时仍有内存与耗时成本。
- 校验为静态数据检查，不验证实体的运行时可达性（如落点是否在实心碰撞里）。
- 试玩进程跟踪基于 Windows `tasklist` 轮询；其它平台上不跟踪（视为运行中）。
- 批量属性编辑不处理 `entity_ref` / `map_ref` 字段（批量改引用会让配对关系失真）。
- 对齐/分布按实体中心点排序与对齐，不考虑实体图幅尺寸差异。
- **不做瓦片自动拼接（autotile）**：有意选择手动选格，避免自动规则不可控。
- 碰撞自动生成是辅助功能，生成后仍可手改；「仅顶部/仅外轮廓」按四邻判定，不做斜角规则。
- 关卡清单的 `unlock` / `secret` 只存数据，解锁逻辑由游戏侧实现。
- 无图集编辑器入口；新增瓦片件套需直接改清单。
- 侧边面板固定 300px 宽：地图/关卡/校验列表都是单行文本（`ItemList` 不渲染 `\n`），完整信息放 tooltip；世界拓扑图节点宽度随面板收缩，面板再窄会退化成单列。
- 地图序列化只有一条路径：编辑器的 `editor_canvas.extract()`。游戏侧 `MapLoader` 只读（`build`/`load_json`），不再提供反向写回，避免两边格式分叉。
