# 关卡编辑器 — 功能文档

> 独立 Godot 4.7.2 工程，通用 2D 关卡编辑器（不绑定具体游戏）。入口场景 `src/editor.tscn`，主脚本 `src/app.gd`。
> 编辑器不依赖游戏工程资源，只读 `<游戏项目>/editor/editor_manifest.json`、`maps/*.json` 与 `content/`。
> 凡本文与代码冲突，以代码为准。

---

## 1. 总体架构

**这个编辑器是什么**：一个不写死任何游戏内容的「组装器」。游戏工程放一份清单
（`editor/editor_manifest.json`），编辑器按清单摆出图层、瓦片、实体、功能；
你在画布上摆地图、给实例挂功能填内容，编辑器把结果存成地图 JSON 和内容 JSON，
游戏侧只读这些文件、自己实现行为。

设计原则：**清单驱动**。图层、图集、实体类型、功能声明与挂载、试玩命令全部来自清单；
编辑器只编辑数据，不硬编码游戏内容。

架构模式：`app.gd` 与 `editor_canvas.gd` 是两个**宿主**，只保留引导代码与同名薄包装，功能实现在
`RefCounted` 控制器里（`preload(...).new(self)` 装配，经 `app.` / `cvs.` 访问宿主状态）。
外部调用点一律走宿主同名包装器，拆分对调用方透明。

> 注意：`app.gd` → 控制器 → 再一层控制器 的委托链里，凡是含 `await` 的函数，**每一层都必须 `await`**。
> 漏一层协程会被丢弃、调用方立刻返回（语法合法，`--check-only` 查不出）。

## 1.1 快速上手

**启动**：用 Godot 4.7.2 打开本工程（主场景 `src/editor.tscn`）直接 F5；或
`godot --path "<Level Editor 目录>"`。

**首次启动**：启动页列出已登记项目，或「打开项目文件夹…」选一个新工程（内含
`editor/editor_manifest.json` 与 `maps/`）；下次自动打开上次的项目，
顶栏「设置 ▾ → 切换项目…」可回项目列表。清单读取失败在选择页直接给出错误说明。

**日常流程**：

1. 顶栏左侧「设置 ▾」→ 新建地图（填名字）或打开已有地图。
2. 左栏顶部「层：…」下拉选当前层（层栈 + 碰撞元层；「管理」可新建/改名/排序/删层）。
   **语义跟资产走**：选瓦片 = 涂刷，选实体 = 放置；落点 = 当前层。没有工具按钮要选。
3. 左栏下方资产列表跟着选中的资产种类切换（瓦片 / 实体）；碰撞元层显示类型/形状下拉。
4. 画布上左键拖动 = 放置/涂刷，右键拖动 = 擦除/删除。
5. 点选实体后画布下沿出现信息条（类型 + 实例码 + 内容状态 + 「在工作台编辑 →」）。
6. `Ctrl+S` 保存；顶栏「▶ 试玩」保存并在游戏里跑当前地图。

**三个平级一级入口**：`关卡`（画布）/ `内容`（给实例挂功能、填内容）/ `资产`（图鉴、实例分布），
`Esc` 从后两者回关卡编辑器。**演出不是一级入口**——它是「某个实例上某个功能的步骤」，从内容编辑器的
绑定行「编辑演出」打开（子面板，非独立页）。顶栏「地图 ▾」管切换，「设置 ▾」管新建/保存/尺寸/导出等
地图级动作；内容与资产页共用同一套顶栏片段，`Ctrl+S` 按当前视图分派保存目标。

## 2. 项目接入

| 功能 | 说明 |
|---|---|
| 项目列表 | `user://settings.cfg` 存 `projects/dirs`（最近使用倒序）、`projects/names`、`projects/last`；兼容旧单项目 `project/dir` |
| 选择项目文件夹 | 启动页列出已登记项目（项目名 + 路径 + 打开/移除记录），底部「打开其它项目文件夹…」用 `FileDialog` 选新目录 |
| 记住上次项目 | 每次打开项目写入 `projects/last`，下次启动自动打开 |
| 切换项目 | 顶栏「设置 ▾ → 切换项目…」：有未保存修改先确认，然后清空清单/画布/撤销栈回选择页 |
| 移除项目记录 | 选择页每行「移除记录」——只删记录不动磁盘 |
| 清单校验 | 读 `<项目>/editor/editor_manifest.json`；缺失/解析失败/结构无效都进错误页，附问题路径 |
| 项目名展示 | 顶栏最左显示 `projectName` |
| 路径推导 | 读后自动补 `_dir`、`_maps_dir`、每个 `shape=tile` 资产的 `atlas_abs`、`_warnings` |
| 清单版本 | 缺 `version` 补 1（结构演进时的迁移锚点） |
| 内置种类合并 | `builtin_kinds.merge_into` 把 `trigger_zone` 补进 `assets`（`kind=entity, builtin=true, visual:rect, sizeFields:[w,h]`），写盘前剥离 |
| 实体身份码补发 | `assets[].code`（kind=entity）缺失时补发 4 位码，随清单保存写回 |

清单里编辑器实际消费的键：

| 键 | 用途 |
|---|---|
| `projectName` | 顶栏品牌 / 窗口标题 |
| `tileSize` | 瓦片像素尺寸，标量或 `[w,h]` 矩形格（默认 16） |
| `screenSize` | 游玩视野预览框尺寸（默认 `[640,360]`） |
| `assets[]` | **统一资产表**：`kind` 分 `scene`/`entity`；scene 用 `shape` 分 `tile`（`atlas`+`cell`+`palette[]`）与 `image`（`texture`+`editorSize`+`anchor`）；`anchor` 对两类都成立（缺省 `center`） |
| （`assets[]` 里 `kind=entity` 的条目） | 实体类型：`id` / `name` / `thumb` / `prefab` / `editorSize` / `sizeFields` / `functions[]`（自带功能挂载）/ `fields[]` / `role` / `code` / `visual` |
| `functions` | 功能声明池：`{fnId: {name, code, fields[], triggers[], timing, view}}` 或数组；实体类型从中挂载 |
| `conditions` | 条件声明池：`{condId: {name, fields[]}}` 或数组；条件无执行码，被功能声明链引用 |
| `steps` | 步骤池：`{stepId: {name, code, fields[]}}`；演出功能（`"steps": true`）的步骤主体，条目码/字段码三池同空间 |
| `functions[].timebase` | 可选：`seconds`（缺省）/ `frames` / `beats`——演出时间轴刻度/吸附单位（R-10），数据形态不变 |
| `audio` | 音频池：`{audioId: {name, code, path, previewPath?}}`；choice 字段 `audio:` 的选项来源，时间轴可试听项目内源文件 |
| `triggers` | 时机池：`{triggerId: {name, code}}` 或数组；**无字段**，功能声明 `triggers` 白名单引用，绑定写时机码 |
| `playCommand` | 试玩命令模板，支持 `%mapfile%` / `%projectpath%` |
| `godotExe` | 可选：覆盖 `playCommand` 里的可执行文件（支持 `%projectpath%`） |
| `contentDir` | 可选：内容根目录，默认 `content` |
| `viewports` | 可选（C5）：具名参考画幅 `[{id, w, h}]`，`viewport_ref` 字段的下拉来源 |
| `views` | 可选（C5）：参考视图 `[{view_id, image, pixel_size, hotspots, layout}]`，可在内容工作台编辑参考图、热点和布局 |
| （`assets[]` 里 `ports[]`） | 可选（C3）：端口声明 `[{id, x, y, type?}]`，`port_ref` 字段的候选来源 |
| （字段 decl 的 `of: "record"` + `fields[]`） | 可选（C1）：结构化行数组的子字段声明 |

参考视图的「布局编辑」支持拖出面板、文字或按钮；可微调锚点和像素偏移、调整叠放顺序、
输入文字与游戏样式 ID、连接内容目标。可切换预览画幅检查响应效果，切换时不改设计画幅。
按钮可设初始焦点和方向目标，按「试玩焦点」后用方向键、Tab、确认测试，确认结果显示在弹窗底部。
禁用按钮聚焦、换成非按钮类型或删除按钮时，会移除指向它的焦点设置。
可添加语言并编辑所选语言的文案、设置字号和显式换行。预览可同时切换语言和画幅；
没有译文时使用上一级语言或原文，文字超出元素范围时描红并提示。
布局元素可从项目目录的图片资产中选图，按完整显示、裁切填满或拉伸实时预览。保存时只记资产 ID 和适配方式。
诊断会定位已失效的图片引用；被布局使用的资产不能永久删除，需先替换或移除引用。
项目声明游戏渲染能力后，可在同一弹窗看游戏渲染的当前画幅和语言。它取未保存布局的快照，
不写正式文件；返回编辑即可继续修改。没有适配器时仍可用编辑器自带布局和焦点预览。
声明 `mapFrame` 后，「设置 → 关卡游戏画面预览」可用游戏渲染未保存的地图、当前相机取景和暂存内容。
可以在实景窗口输入取景中心 X/Y（地图根空间像素）与缩放，再重新渲染；取景只影响该窗口。留空或点「默认取景」可还原：本图沿用画布相机，跨图按目标图范围取景。更改取景会清除旧画面和未确认的选点。
游戏若输出实景选点区域，可选中资产后在预览里点击并确认，将实例准确放在映射的图层锚点；
实例、格、端口和格边的单值引用字段可用「实景选…」拾取合法候选，功能与步骤的嵌套记录和条件参数也支持此入口。配对地图字段指向另一张地图时，使用该地图的已保存实景；嵌套字段按所在行的配对地图取景，确认不切换关卡。
多选实例和格字段也可从实景中逐个切换目标，一次应用整个列表。保留原有选项的顺序，新选项按点选顺序追加；右键恢复打开时的选择。
有序实例或格数组可在实景左键追加途经点、右键移除末项，同一目标可重复加入。也可在表单逐行替换、复制或调序，适合巡逻和镜头路径。
内容也能通过声明的参考视图字段选定要打开的屏幕，屏幕上的按钮可继续跳到另一条内容。
「复制视图」将当前画面复制为待命名的草稿；布局中也可复制单个元素，副本使用新的元素 ID。仍有内容引用的视图会列出引用位置并阻止删除。
声明了地图取点的二维坐标和点数组可直接点选映射区域，支持空地上的镜头焦点和自由路径。点数组可连续描点、撤掉末点，再一次确认；仍可在表单输入精确坐标。字段也可绑定同一记录内选定的图层，实景只从该层的可见区域取点，保存图层局部像素，适用于分层路线和锚点。
分屏中每个视区可用不同的图层或投影映射。选中多边形或路径资产时，左键在同一图层描点，
右键撤掉末点；形状有效后可确认创建，一次撤销。游戏可标明不允许穿透拾取的遮挡面。
选中瓦片笔刷时，左键拖动涂刷、右键拖动擦除；可跨映射图层，路径在遮挡和未映射区域断开。
预览标记和格数只显示草稿，点「应用笔画」后一次写入和撤销。
选中根碰撞层后，可在提供根空间映射的实景画面上用相同手势刷擦碰撞，沿用当前笔刷的类型和形状。
碰撞映射可以与瓦片映射不同；笔画不会修改瓦片，也不会穿过遮挡区或连接没有根空间映射的区域。
「设置 → 实景设置出生点」在同一根空间映射上选点。确认后出生点对齐根格中心，一次撤销；根碰撞层锁定或越界时不能应用。
「设置 → 实景编辑格图」可在根空间或已有格图空间描绘新格，也可按顺序点两个已有格，添加或移除起点的单向邻接。确认后刷新画面，每次应用可撤销。
「新建独立连接」沿用清单声明的连接类型、默认值和属性控件；再点起点与终点可创建带独立 ID 的有向边，同一对格可有多条边。
「编辑独立连接」先点起点格，再从它的出边中选一条。可修改已有属性、重选终点或删除连接，改接保留原边 ID。
新建及改接独立连接时，选好起点（改接还须选中出边），可以点本图终点，也可以选择其他地图并从其已保存游戏画面点终点。确认目标后回到源图草稿，应用才写入连接并记录一次撤销。目标地图须有唯一地图码，游戏须在该画面提供格拾取区。
「编辑格顶点」先选游戏标出的顶点，再点同空间的新位置。Shift + 点顶点可在其后插点，Ctrl + 点顶点可删除。确认后保留格 ID、邻接和独立边；手工调整的生成格不再带有瓦片生成标记。
「删除格」点选后确认，移除该格及其出边和本图入边，可一步撤销。其他地图和内容对该格的引用需要另行改接。
「设置 → 实景调整实例和轮廓」可先点游戏标出的已有实例或顶点，再点同层的新位置，最后应用。
移动实例保留实例码、绑定和引用；移动顶点保留其余轮廓，验证失败时不写。右键重选，一次撤销。
Shift + 左键选已有顶点，再点同层位置，可在所选顶点之后插一点；Ctrl + 左键选顶点可拟删除该点。
两种操作都需应用确认。开放路径至少保留两个顶点，闭合轮廓及孔洞至少保留三个。
也可用「实景工具」选中已有实例，确认旋转 90°、水平翻转或删除。每次操作单独撤销；删除不会自动改接引用。
「复制实例到选点」先选原件，再点可见且解锁的目标图层。副本保留变换和组外引用，获得新实例码；实例专属内容复制到暂存，随保存或试玩发布。
「实景工具」可切换到绘制附加外环或孔洞：先选闭合实体或其顶点，再在同层描点；右键撤掉末点。
孔洞必须完全位于某个外环内。删除工具点附加外环或孔洞的任一顶点，再确认删除整环；主外环保留。
每次应用后会在同一窗口保留所选画幅、清空旧选点，并重新渲染工作副本，可接着调整其他实例或顶点。
若出图失败，已应用的编辑仍保留，可点「渲染关卡」重试。
改变画幅或地图后需重渲染。
可选当前画布大小或项目画幅；结果是单帧，预览不保存地图或内容。
声明 `timelineFrame` 后，演出面板的「游戏演出画面」按项目画幅取样，起始位置来自播放头。
可在同一窗口输入其他秒、帧或拍位置，按回车重新渲染，不移动编辑器的播放头。
游戏接收已应用的演出工作副本；实例演出还可在当前未保存地图里按当前相机及选定绑定取样。
渲染期间更改地图、相机或同图暂存内容时，需要重新取样。

**图层**：地图 `meta.layers` 逐图声明（见 §4.1）。
碰撞类型集由清单 `collisionTypes` 声明（缺省池 = 内置四类 solid/one_way/ladder/hazard；
声明即整体覆盖），`gameplay` 标签由游戏侧 `map_loader` 消费实现行为。

> 游戏工程该怎样声明清单/读地图/实现功能，见 **[GAME_SIDE_STANDARD.md](GAME_SIDE_STANDARD.md)**（数据契约唯一权威）。

**实体占位尺寸**：`editorSize: [w,h]` 优先；否则读 `prefab` 的第一个碰撞形状
（Rectangle 用 `size`，Circle 用 `radius*2`，Capsule 用 `radius*2 × height`）；都没有 = 用 1 格（tileSize 尺寸）。

**角色声明**：`assets[].role` = `portal` / `exit` / `landing` / `trigger`（连接语义标签）。
**只认清单显式声明**——未声明的实体就是普通实体，画布不猜、不画连接标记（零兼容）。

地图 JSON（与游戏侧 `MapLoader` 同构）：

```json
{
  "version": 7,
  "meta": { "name": "level_1", "w": 120, "h": 56, "code": "K7QM",
			"layers": [{ "id": "L1C3", "name": "资产层", "visible": true },
					   { "id": "T8N5", "name": "远景", "visible": true, "parallax": 0.5, "ySort": false, "offset": [0, 0], "scale": 1.0 }] },
  "spawn": [2, 2],
  "tiles": { "L1C3": [[x, y, "terrain", ax, ay, 0]], "T8N5": [[x, y, "decor", ax, ay, 0]] },
  "collision": [{ "x": 21, "y": 24 }, { "x": 30, "y": 12, "type": "one_way", "shape": "r45" }],
  "objects": [
	{ "asset": "crawler", "code": "B3XD", "layer": "L1C3",
	  "x": 10.5, "y": 8,
	  "props": {},
	  "functions": [{ "fn": "X7K2", "content": "K7QM-D4L3-B3XD-dialogue-A9FK2P",
					  "name": "初遇", "order": 1, "parallel": false }] },
	{ "asset": "bg_forest", "layer": "L1C3", "x": 0, "y": 0 }
  ]
}
```

约定：

- 瓦片按层存：`tiles` 键 = 层码，数组条目 [x, y, 资产id, ax, ay, alt]，第 3 位是**资产 id 字符串**，第 6 位 = 变换位 0-7（R 旋转/X 翻转，笔刷态见状态栏提示）
  （指向清单 `assets[]` 里 `shape=tile` 的条目），4/5 位是图集内格坐标。切片尺寸取该资产的 `cell`
  （可为非正方形、可大于地图格），不写在地图里——换图集/重排 `assets[]` 都不会破引用。
- `collision` 条目为**对象**（v6）：`{x, y}`，`type` 缺省省略（solid）、`shape` 缺省省略（矩形）；
  类型集由清单 `collisionTypes` 声明（缺省池 = 内置四类，声明即整体覆盖）。
- `objects[]` 统一收**场景图片实例**（`kind=scene`、`shape=image`）与**实体实例**（`kind=entity`）：
  同形，差别只有 `code`——只有实体才产实例码。`scene` 键非法（实体实例键是 `asset`）。
  `transform` 缺省整键省略；`visible`/`zPolicy`/`sortAnchor` 同样缺省省略。
- `x/y` 是**浮点格坐标**（可半格、可超出格），锚点换算见 `GAME_SIDE_STANDARD` §3.4。
  关掉吸附后拖到半格处，保存重开仍在原位（吸附默认开）。
- 实体 `props` 保留所有未知键（只有空值被丢弃），不做白名单剥离——手工预留字段不会在保存时蒸发。
- `layer` = 层码，缺省最底层。

**格型扩展（B3，均在 `meta`，缺省省略）**：

| 键 | 取值 | 说明 |
|---|---|---|
| `gridProjection` | `orthogonal` / `isometric` / `hexagonal` | 逐图投影（B1）；缺键沿用项目解析（任一瓦片资产声明非正交即整项目按它）。有内容的图切换需显式转换 |
| `gridTopology` | `quads`（缺省）/ `triangles` | 三角格：每列平行四边形切成两个半格。格号 `(i, row)` 的 `i` 是**三角列**（`c = floor(i/2)`，奇偶选半格）；偶半格顶点 `(0,0),(1,0),(0,1)`，奇半格 `(1,1),(0,1),(1,0)`。拾取按对角线 `x+y=1` 分半格，邻接 = 三边各一邻格；瓦片数据仍是同一份六元组，由自绘层按三角形轮廓贴图集切片。六边形投影没有平行四边形列，组合被校验拒绝 |
| `gridBasis` | `[[ux,uy],[vx,vy]]` | 双基向量斜平面：`to_px = g.x·u + g.y·v`，逆矩阵反算。拒绝非有限数与不可逆基（共线/零向量）；画布、导出、校验共用同一份解析 |

桌面作者流程已覆盖等距、六边、自定义斜基三角和自定义斜基四边格：在新建弹窗选格空间，在画布刷路线和碰撞、设置出生点和摆放终点门，保存重开后由独立游戏进程读取并走到终点。验收检查拾取与共边规则，未对比图集像素或遮挡效果。

## 4. 画布与图层

### 4.1 图层栈（层 = 纯 z 槽 + 三段遮挡容器）

图层来自**地图 `meta.layers`**（不是清单）：新建图默认「资产层 / FL」两层（纯命名约定），
用户可自建任意数量的层。数组序 = 栈序（底→顶）= 绘制序，跨层只认栈序、全程不写 `z_index`；
**一层可混瓦片与实例**。层条目可选参数（缺省省略）：

| 参数 | 语义（编辑器预览） |
|---|---|
| `parallax` | 视差系数（0–1）：画布按相机位移反向平移，远景半速、0 = 固定 |
| `ySort` | 层内瓦片与实例一起按排序点 y 绘制（层容器建三段：below / YSort / above） |
| `offset` / `scale` | 层容器的整体偏移与缩放，画布直接生效 |
| `blend` | 层混合模式：`mix`（缺省）/ `add` / `mul`，画布挂 CanvasItemMaterial 预览 |

**遮挡模型**：每层建 below / YSort(含瓦片与 auto 实体) / above 三段容器，
实例按 `zPolicy` 入段（缺省 auto）；排序点 = 资产 `anchor` + 实例 `sortAnchor` 覆盖，
瓦片排序点 = palette 条目 `ySortOrigin`（缺省切片底部）。
层未开 `ySort` 时 YSort 段退化为摆放先后；同层混放但没开 ySort 会给状态栏提示。
混合模式在层管理弹窗每层「混合」下拉可改（mix/add/mul）；parallax/ySort/offset/scale 手改地图 JSON。

左栏顶部「层：…」下拉列**栈层 + 碰撞元层**（碰撞不在层栈里，排最后），
旁边「管理」按钮弹**层管理弹窗**：

| 操作 | 行为 |
|---|---|
| 新建层 | 插到栈顶之下（新建即可画前景遮挡）；层码出生即定 |
| 改名 | 只改显示名，不破引用（引用走层码） |
| 上移 / 下移 | 换栈序 = 换遮挡关系（一次撤销步） |
| 运行时可见 ☑ | `visible` 初始态，差分视图用（编辑视图显隐是另一回事） |
| 删除 | 删除该层的瓦片与实体，至少保留一层，可撤销。删层前列出受影响的地图、内容与草稿引用；原字段值保留，便于重新选择 |

**图层显隐（👁）**只影响编辑视图显示，不影响数据；**图层锁定（🔒）**在写入入口
（涂/擦/放置/拖拽/区域操作）逐处守卫，绕过 UI 直调也会被拦。
换图时显隐/锁定清空（撤销恢复同图时保留）。

### 4.2 语义跟资产走（place_kind）

没有工具概念。左栏选中什么资产决定左键行为，落点 = 层下拉的当前层：

| 选中资产 | 左键 | 右键 | 左栏内容 |
|---|---|---|---|
| 瓦片 | 放置当前瓦片，拖动连续涂（碰撞元层 = 画碰撞块） | 擦除（当前层命中实体删实体，否则擦瓦片/碰撞） | 瓦片调色板 |
| 实体类型 | 放置当前实体（落当前层；碰撞元层拒绝） | 删除命中的实体 | 实体列表 |

实体单选 / 框选 / 拖动 / 出生点拖动**与层无关**（任何层都可以选实体）；
出生点拖动在实体放置模式下可用。

### 4.3 瓦片调色板（两级导航）

- 顶层：多图集时先列**图集**，钻入后列该图集的**类别**，再进**资产**；单图集直接进类别层。
- 类别名优先取 `palette[].cat`，无 `cat` 用图集条目名（一个图集 = 一个默认类别），都没有 → 「未分类」。
  类别行显示「→ 类别名（数量）」，进入后首行是「← 返回」。
- **最近使用（MRU）**置顶，会话内最多 8 格，键为 `资产id:x,y`。
- 缩略图 40×40（纹理缓存按资产 id + 格坐标复用）；左栏宽 200px 时 3 列 × 56px，长名省略号 + tooltip。
- 清单没配 `palette` 时退回「整张图集逐格铺满」，每格都是可选瓦片。

### 4.4 碰撞元层

碰撞类型/颜色/形状由清单 `collisionTypes` 声明（缺省池 = 内置四类，声明即整体覆盖）；
画布色块按声明的 `color` 分色（未声明按 id 稳定取色）。

- 左栏两组下拉：**类型** 来自 `collisionTypes`（显示名 + 类型 id）；
  **形状** 矩形 / `r45`（右高斜坡）/ `l45`（左高斜坡）。
- 碰撞格数据上是碰撞 TileMapLayer 的隐形格（`INVISIBLE_CELL = (4,0)`），
  显示交给专属节点 `CollisionView`：按声明分色分形，斜坡画三角形。
  直接显示 TileMapLayer 会画出图集那格灰白分块。
- 该 TileMapLayer 用**编辑器自建的 5×1 切片源**（R20），与用户图集完全独立——
  删掉/换掉图集、图集读不出来，碰撞录入与显示都照常工作。
- 类型/形状只在非缺省时写入地图（`solid` + 矩形 → 只写 `{x, y}`）。
- 「自动生成碰撞…」按**当前层**瓦片推导碰撞（当前层自审）：

| 策略 | 行为 |
|---|---|
| 全部地形格 | 每个有瓦片的格子都生成 |
| 仅顶部表面 | 只给「上方无瓦片」的格子生成 |
| 仅外轮廓 | 只给四邻有不空位的格子生成 |

  可选「先清空现有碰撞再生成」与「只碰顶面（one-way）」（仅顶部表面策略下生效）；
  整件事一个撤销步；碰撞元层锁定时拒绝。手动摆放仍是首选方式。

### 4.5 视图与画布绘制

- 滚轮缩放（0.5×–6×，以鼠标为锚点），中键拖动或**空格 + 左键**平移。
- 状态栏右侧「网格」开关；碰撞显示跟随图层显隐。
- 画布绘制内容：网格、地图边界、幽灵预览（瓦片范围框 / 实体缩略图 + 占位框 / 内置种类 2×2 矩形）、
  出生点十字（实体放置模式实色、其余淡色）、游玩视野框（鼠标处 + 出生点各一个 `screenSize` 框）、
  实体引用连线（同图黄线 / 跨图蓝紫线）、出口 ↗ 角标、传送落点描边、选中高亮、框选矩形、
  多选外接框（含「N 个实体 · 拖动可整体移动」提示）、实体实际占位框、
  `visual: rect` 实体的半透明矩形（颜色/透明度读资产声明）、区域选区轮廓、
  区域拖动/粘贴幽灵预览。
- 没打开地图时禁用全部编辑交互，画布中央给引导。

## 6. 实体编辑

### 6.1 放置与选中

| 功能 | 说明 |
|---|---|
| 实体列表 | 清单 `assets[]` 里 `kind=entity`（含内置 `trigger_zone`）；无缩略图的按 `visual` 声明画占位图标 |
| 帧动画预览 | 类型声明 `frames[]`（贴图路径数组）时画布按 8fps 循环预览（只确认帧序，播放节奏归游戏侧） |
| 放置 | 实体放置模式下左键点格 → 落一个 `EntityNode` 到**当前层**，位置吸附到锚点所在格；关掉状态栏「吸附」后按像素落位（存浮点格坐标） |
| 放置即选中 | 放下后立刻发 `entity_selected`，「放置 → 配置」不断档；连放不受影响 |
| 实例身份 | 每个实例一个 4 位**实例码**（放置/粘贴时在本图活跃实例内查重发放，撞码重摇；复制产生新码、已有码不重编）。唯一身份，引用/重映射/连线全用它 |
| **实例参数** | 内容编辑器右栏「实例参数」按资产的显式 `kind: input/choice` 声明显示标量、数组、记录及选项。支持从游戏画面拾取地图或指定图层的坐标、有序路径及可拾取引用。确认后按字段 ID 写入地图实例 `props`，支持实例差量撤销和重做。默认值只显示，编辑后才写覆盖值 |
| **引用编辑** | 内容编辑器右栏「引用」区：`entity_ref` 按声明列本图或配对图实例，`map_ref` 列地图，`edge_ref` 和 `port_ref` 列对应的对象引用。值写实例 `props` 并进撤销栈；本图实例引用可在画布和预览中高亮 |
| **实例级来源** | 功能字段 `kind: choice` + `source: "entity_inst:类型id,..."`：下拉列当前图实例，值=实例码；类型列表空 = 全部实例 |
| **音频来源** | 功能/条件字段 `source: "audio:"`：下拉列清单 `audio` 池（值=音频码）；编辑器不播放音频，播放归游戏侧功能代码 |
| **端口引用（C3）** | 字段 `type: "port_ref"`、`of` = 端口类型过滤（可空）：下拉列**配对图优先**的实例端口（显示「类型码 · 端口id」），值存 `{map: 地图码, inst: 实例码, port: 端口ID}`；复制时只改前两段。端口本身在资产条目 `ports[]` 里声明（`x/y` 为锚点局部像素） |
| **格 id 引用（C4）** | `choice` + `source: "cell:"`：下拉列当前图 `meta.cellGraph` 的 `cell_id`；值 = 格 id 字符串。可点「画布选…」按多边形命中。从「地图 ▾ → 编辑当前地图格图…」可维护多边形与有向邻接；应用随地图保存，支持撤销 |
| **格边引用（§7.4）** | 字段 `type: "edge_ref"`：下拉列地图里「两侧都有瓦片」的相邻格对（按规范代表边去重，显示 `(x,y)-(x,y)`），也可「画布选…」在格边附近点选（就近取垂距最小的共边并高亮）；值存 `{map: 地图码, cell: [x,y], edge: "x1,y1|x2,y2"}`。边身份由格拓扑推导（无向边取排序后的代表边，`EdgeRef.canonical_edge`），不依赖游戏侧声明键 |
| **视口引用（C5）** | 字段 `type: "viewport_ref"`：画幅下拉（清单 `viewports`）+ 归一化 0..1 的坐标 SpinBox；值存 `{viewport, point: [nx,ny]}`，声明 `rect: true` 时存 `{viewport, rect: [nx,ny,nw,nh]}` |
| 实例身份码 | 每个实例带 4 位 `code`（存在于实体 meta，随地图保存），改名/换 id 不变 |
| 单选 | 点实体 → 选中并在画布下沿出信息条 |
| 框选 | 状态栏「框选」开关打开后左键拖动 = 框选；未开时 `Ctrl+拖动` 兼容。选中后外接框内按下可**整组拖动**，松手各自吸附格点，一次拖拽一个撤销步 |
| 命中判定 | 按实体**占位尺寸**做外接框命中（不是写死 16/20 px），命中多个取中心最近者 |
| 拖拽移动 | 按住实体拖动，松手吸附格点；一次拖拽一个撤销步 |
| 删除 | `Del`，或右键点实体（右键只擦当前层：命中本层实体删实体，否则擦瓦片） |
| 朝向翻转 | `F` toggle 单选或框选集合的 `transform.flip_h`，一个撤销步；写入地图 `objects[].transform` |
| 旋转/缩放 | `R` 旋转选中实例 90°（`transform.rotation` 弧度，归一 [0,2π)；瓦片笔刷模式下 R 让位给笔刷旋转）；`[` / `]` 等比缩放步进 ±0.1（下限 0.1，回到 1.0 整键省略）。单个或框选集合，一个撤销步 |
| 尺寸把手 | 带 `sizeFields` 的选中实例（事件区等自定尺寸）右下角紫把手：拖动改 `props` w/h（格数 ≥1）；center 锚点下原点取起手快照，防预览漂移 |
| 顶点编辑（几何段） | `visual.type = poly/path` 的实体：选中画顶点紫把手——拖动改 `props.points`（局部像素、相对锚点）；双击边就近插点；右键顶点删点（poly ≥3 / path ≥2 保底）；全部一个撤销步 |
| 自由绘制 | 左栏选中多边形或路径实体后点「绘制轮廓 / 路径」。左键加点，右键撤末点，Enter 完成，Esc 取消。关吸附可精确落到像素坐标；开吸附则落格中心。闭合轮廓自动连回起点，并拒绝自交、重合或无面积的轮廓。完成后作为普通实体保存、复制和撤销。 |
| 孔洞 | 选中闭合轮廓后点「绘制孔洞」。内环从填充和点选范围中扣除；须完全在外轮廓内且与其他孔洞分离。青色把手可拖动，双击内环边加点，右键把手删点，Shift + 右键点孔洞删除整环。每次有效修改可一步撤销。 |
| 附加轮廓 | 选中闭合实体后点「绘制附加轮廓」，给同一实例添加一个不相连的外环。每个外环可有自己的孔洞，也能直接改顶点。Shift + Alt + 右键点击附加轮廓删除该轮廓及其孔洞；可一步撤销。 |
| 引用连线把手（E2） | `entity_ref` 字段在选中实例上出一个青方块把手（空引用在锚点左上给一小段斜线桩）：拖到目标实例上松手即写入该字段；落点按声明的 `of` 白名单过滤（类型不符的实例不可落）。改目标地图的配对字段（C1）走同一条写入口并先确认清空旧落点。选中信息条提示「N 条引用（拖青点换落点）」 |
| 方向键微调 | 有选中时整格移动（`Shift` = 4 格）；1 秒内的连续按键合并成一个撤销步 |
| 复制粘贴 | `Ctrl+C` / `Ctrl+V` 保持相对布局，粘到光标处吸附到锚点所在格；`props` / `functions` / `transform` **深拷贝**，副本互不影响；内部引用重映射到新实例码 |
| 原位复制 | `Ctrl+D` 偏移 1 格复制，保留属性、绑定和变换；实例专属内容暂存到保存或试玩时发布 |
| 剪切 | `Ctrl+X` 复制进剪贴板并删除选区，整件事**一个**撤销步 |
| 图层锁定守卫 | 涂/擦/放置/拖拽/选区删除/翻转/粘贴/区域操作全部检查层锁——跨层选区逐成员查，任一命中即整体拒绝 |

### 6.2 选中信息条

画布下沿浮一条极简信息条：`类型名 实例码` + 内容状态 + 「在工作台编辑 →」（`Enter` 同效）。
它**不是**属性表单——参数属内容，归内容编辑器与资产目录。没选中时整条隐藏。
信息条右侧有 👁 开关：切换该实例的编辑器可见性（`objects[].visible`，缺省 true，**游戏侧忽略**）——
隐藏后画布点不中它（用来看底下画面），保持选中时再点一次恢复。

### 6.3 区域编辑（瓦片 / 碰撞 / 区域内实体）

| 操作 | 说明 |
|---|---|
| 框选区域 | 瓦片语义（place_kind=tiles）+ 框选开关（或 `Ctrl+拖动`）→ 画金色选区轮廓 |
| 区域复制 | `Ctrl+C` 捕获各层瓦片 / 碰撞 / 区域内实体快照（瓦片按层键、实体带层，按相对偏移存） |
| 区域粘贴 | `Ctrl+V` 进入幽灵预览（瓦片 / 碰撞 / 实体三类都画），左键落位，右键或 `Esc` 取消。实体重新发号，附属内容**每条生成独立文件**；引用按声明重映射（组内换新码、组外保留），配对地图字段补源图/目标图键，无法配对又跨图 = 冲突并取消整次粘贴。新内容先进会话暂存，随正式提交（`Ctrl+S`/试玩）落盘 |
| 区域剪切 | `Ctrl+X` 复制 + 擦源，一个撤销步；任一图层锁定即整体拒绝（部分跳过会让剪贴板与实际删除不一致） |
| 跨层搬动与复制 | 状态栏打开「跨层搬动」，按画布范围框选可见层瓦片、实例及根碰撞。从框内拖动可搬动，Ctrl+C 复制，Ctrl+V 预览、左键粘贴。吸附开启时按根格中心确定统一位移；瓦片和碰撞在目标层格系重新拾取，实例保留像素偏移。跨图按唯一层名匹配，同图优先按层 ID。锁定、越界、目标格占用等都会拒绝整次操作。每次操作一步撤销，复制实例使用新实例码并重连组内声明引用。 |
| 格图与出生点 | 「设置 → 跨层搬动选项」可分别启用两项；默认留在原位。框中的格按多边形重心入选，搬动后保留格 ID、连边和引用；从瓦片生成的格搬动后作为手工格维护。出生点对齐根格，越界时整次搬动不写入。复制时用「设置 → 复制跨层选区选项」：复制的格和有向边使用新 ID、只重连选区内的连接，副本中指向选中格的声明引用随之更新；勾选框内出生点后，粘贴将替换目标地图的出生点。 |
| 规则格边引用 | 「复制跨层选区选项」可启用「副本引用跟随框内规则格边」。原边两端根格中心都在框内且粘贴后的两个根格仍然共边时，副本使用新边；跨框边、其他图的边及无法落到有效共边的边仍指向原位置。该操作只更新副本的声明字段。 |
| 区域拖动 | 在选区内按下拖动整块；**松手才**「推撤销 → 擦源 → 写目标」，中途取消不留半截状态 |
| 瓦片批量替换（E2） | 顶栏「设置 ▾」→「批量替换瓦片…」：按当前区域选区内**出现过的源资产**过滤，选目标资产与目标切片（或「保持源坐标/整图平铺」）；目标图集表达不了的格（越界切片/非瓦片资产）先逐格列冲突且不写；确认后一笔撤销，变换位 `alt` 原样保留 |

区域内实体的「所在格」判定统一走 `EntityNode.cell()`：视觉矩形（`rect()`）的**左上格**。
锚点由资产声明的 `anchor` 决定（缺省 `center`，内置事件是 `top_left`），因此中心锚点的普通实体
与左上锚点的事件不会出现判定差异。复制、剪切、框入、粘贴四处共用这一口径。

### 6.4 出生点

- 出生点画成绿框 + 十字；实体放置模式下可拖。松手只记录起点和终点；拖回原格或取消时不留历史。根碰撞层锁定时不可移动。
- 出生点位置存 `spawn: [x,y]`（格坐标）。

### 6.5 事件（内置种类 `trigger_zone`）

`trigger_zone` 由编辑器提供，游戏工程清单不需要声明：

- 并入清单（`builtin=true`，固定实体码 `TZ99`），保存清单时剥离，不污染游戏工程。
- 显示名「事件」——摆在哪层都行（可专门建一层摆事件）。**它没有任何特殊语义**：
  就是一个 `visual: {"mode":"rect", ...}` 的实体资产（`type` 缺省 `rect`；`mode` 决定无贴图时画布画半透明矩形），尺寸走通用 `sizeFields: ["w","h"]`
  （格数，`props.w/h`）。"什么时候触发、触发做什么"全在绑定的 `functions[]` 里
  （功能的 `timing` 声明 + 绑定的 `trigger` 时机码）。
- 没有 `thumb` 也出现在实体列表里；放置时画 2×2 矩形幽灵，落下带默认 `props {w:2, h:2}`，
  位置按 `anchor: "top_left"` 落在矩形左上格。
- `w/h` **有**画布把手：选中事件后拖右下角紫方块改尺寸（格数，一次拖动一条撤销）；
  没有独立的「事件属性」表单，也没有数值输入框。保存时 `props` 只丢「值为 null/空串」的键，其余原样保留。
- 画布绘制：半透明矩形，颜色/透明度读资产的 `visual` 声明，无事件 id / 触发方式标签。
- 绑定行（内容编辑器右侧功能列表）提供**时机下拉**（写 `functions[].trigger`，时机码）与
  **启用勾选**（写 `functions[].enabled`，仅 `false` 落盘）。

## 7. 内容系统（实例 → 功能 → 内容）

### 7.1 模型

- **功能由项目侧实现**，编辑器只暴露「可编辑内容」接口。
- 功能在清单顶层 `functions` 声明：`{fnId: {name, code, fields:[...], triggers:[...], timing:{mode}, view:{}}}`。
  字段按 `kind` 两分支：`input`（string/int/float/bool/color/vector2/range/asset_ref/array/port_ref/viewport_ref/edge_ref；
  string 可 `multiline`；array 用 `of` 指元素类型、可增删行，`of: "record"` + `fields` 声明子字段即**结构化行**
  ——每行带 ↑↓/复制/删除，子字段可再嵌 array，限深 4）
  与 `choice`（`options[]` 或 `source` 动态选项，`multiple: true` 切勾选组）；认不出的声明只读展示，绝不提供可写控件。
  `triggers` 是引用 `triggers` 池的可选时机白名单，`timing`/`view` 编辑器只存取。
- **实例绑定**存在实体 meta / 地图 JSON 的 `functions` 数组里：

```json
"functions": [
  { "fn": "X7K2", "content": "<内容ID>", "name": "初遇", "order": 1, "parallel": false,
	"trigger": "T111", "enabled": false }
]
```

| 字段 | 含义 |
|---|---|
| `fn` | 功能**执行码**；码未在清单声明只**警告**（允许先放数据后补声明） |
| `content` | 内容条目 id；空串 = 还没填（界面显示「未填」），不是错误 |
| `name` | 内容显示名（列表读这个） |
| `order` | 组内顺序；**顺序即执行顺序** |
| `parallel` | 编辑器只存取不解释（游戏侧常用语义：与前一项同时触发） |
| `trigger` | 可选时机**执行码**（取自功能声明白名单）；缺省省略 = 默认时机 |
| `enabled` | 可选布尔；缺省省略 = 启用，只有 `false` 落盘 |

- **内容文件**：`<项目>/content/<功能id>/<内容id>.json`，结构
  `{id, function: 执行码, name, fields:{字段码: 值}}`。
- **复用有两种**：**复制成新 ID**（库按钮，独立一份文件，改一份不影响别人）与
  **共享改绑**（C2，本实例直接指向已有内容；确认框先列出还有谁在用同一条，改了会一起变）。
- **码表**：保存清单时自动生成 `editor/CODES.md`（人类名 ↔ 执行码对照）；游戏侧启动读清单
  重建同款映射，改名不破引用。
- **引用类字段的取数域（C1）**：声明了 `mapField` 的 `entity_ref`/`port_ref`/`edge_ref`，候选来自**同一行/同一内容里
  那个地图字段的当前值**（不是「当前打开的地图」）；没配对字段就是本图。结构化行里作用域收窄到**本行**。

### 7.2 分层身份码

五段：`地图-实体类型-实例-功能-内容`。

| 段 | 长度 | 载体 | 发放时机 |
|---|---|---|---|
| 地图 | 4 位 | 地图 `meta.code` | 首次载入该图时补发 |
| 实体类型 | 4 位 | 清单 `assets[].code` | 读清单时补发；内置种类固定（`TZ99`） |
| 实例 | 4 位 | 实体 meta `code`（随地图保存） | 放置/载入时补发 |
| 功能 | 4 位 | 清单 `functions[].code`（人类 id 只显示；执行引用写码） | 读清单时缺则补发 |
| 内容 | 6 位 | 内容 id 末段（第四段仍是功能人类 id，显示壳） | 创建内容时随机发放 |

字符集 `ABCDEFGHJKLMNPQRSTUVWXYZ23456789`（去掉易混的 I/O/0/1）。
**名字完全退出 ID**：地图名、类型名都只是展示层，改名不影响任何运行时引用。
任一段缺失时 `content_id()` 返回空串，不产出脏 ID；`unique()` 冲突时只换末段内容码。

### 7.3 内容编辑器（工作台 →「内容」）

左列「项目内容库…」可在没有地图和实例时创建内容。选功能类型后填写功能与条件字段，
点「保存」写入内容资源文件；有演出声明时可保存后直接打开同一文件的步骤列表和时间轴。
可重开已有内容，或从实例的内容库共享绑定。项目级内容由游戏侧按功能目录与内容 ID 读取，
从地图复制时保留共享引用。项目内容表单和步骤编辑器的「本图候选」可临时选一张地图，
列出其中的实例、端口、格边、有限格图单元和图层；也可打开实景点选实例、格、端口和格边。
选择仅用于编辑，随「保存并编辑演出」带到步骤面板，
不会写入内容或切换画布。字段已选的配对地图优先；运行时所用地图仍由绑定或跳转契约决定。
左列「参考画幅…」可添加画幅或更新宽高，
原有引用的画幅 ID 和归一化坐标保持不变。左列「参考视图…」可加载项目内图片；
按等比预览拖绘归一化矩形，点击选中，可删除或选择跨功能内容目标。
它可作为菜单、对话或其他画面的参照；游戏决定如何布局和响应点击。

内容库中的「流程关系…」显示全项目已保存内容与参考视图。可按功能、内容 ID 或视图 ID 选节点，也可在滚动画布上点选；
列表呈现功能、条件和步骤直接声明的内容引用，包括未设置字段、多选的添加位置和失效目标。
声明的屏幕字段可以接到参考视图，屏幕的按钮和热点可以接到内容。选中屏幕可以直接打开布局编辑。
如果游戏工程在窗口打开时移除了目标，点「重新扫描」更新关系。「待修引用」列出无法解析的内容或屏幕目标，
选中一条即可跳到实际的源内容与字段，包括内联的分支或条件行。
选择目标并应用可接线、改接或断开，修改写回内容字段或清单中的布局元素与热点；
可在原内容或步骤表单里增删和编辑数组记录、条件行；保存后也能在关系图改接其内联引用。
游戏工程实现实际推进、条件判断与循环语义。

三列布局：

| 列 | 内容 |
|---|---|
| 左列 | 本图实例列表：类型名 + 实例码；整行是按钮，点击与画布双向同步（保持放置顺序）。**筛选（E2）**：名称/实例码搜索框 + 图层下拉 + 资产下拉，三者叠加；标题显示「命中/总数」，空结果与「本图没有实例」分开给空态 |
| 中列 | 只读画布预览：重绘网格 + 各层真实瓦片 + 实例缩略图/色块 + 选中框；滚轮缩放（鼠标锚点）、中键平移、左键点选/悬停；引用字段选中目标 → 亮青粗框指向预览 |
| 右列 | 选中实例：类型名 + `地图名.实例码` + **引用区**（类型声明了 entity_ref/map_ref 就出下拉，值写 props、进撤销栈）+ **功能列表**（挂载自动补齐 + 手动添加；🔒 = 类型自带不可删）+ 选中项的内容表单 |

**附加功能行**：`① 功能名 [内容名] ↑↓ 时机▾ ☑启用 ⟳并行 [库] ✕`

| 操作 | 说明 |
|---|---|
| 点行 | 展开该功能的内容表单 |
| 「↑↓」 | 与相邻一条交换执行顺序（`order` 按交换后的数组序重排；选中的表单跟着行走） |
| 「+ 添加功能 …」 | 列出未绑定功能；声明 `repeatable: true` 的功能已绑定后仍可添加，并显示已有行数 |
| 「库」 | 列同功能的全部内容条目（**C2**：名称/id 搜索 + 引用状态筛选 + 每行 `◆n` 入边数；选中一条后下方显示「被哪些实例绑定 / 哪些内容引用它」）。三个动作：**复制成新 ID**（复制文件并改绑当前行）、**共享改绑**（本实例直接指向选中条目，不复制；确认框先列受影响实例）、**改显示名 / 删除**（删除前跑引用检查）。跨功能不列（字段声明不同，复用没意义） |
| 「时机 ▾」 | 该功能声明的 `triggers` 白名单 → 写绑定 `trigger`（时机码）；首项「默认时机」= 删掉该键 |
| 「启用」勾选 | 写绑定 `enabled`：勾上 = 删键（缺省即启用），取消 = 写 `false` |
| 「⟳并行」 | 切换该条的 `parallel` |
| 「✕」 | 只解除绑定，**内容条目留在库里**（删绑定 ≠ 删内容） |

重复行的时机、启用、顺序和内容可以分别设置。新行有实例内稳定的 `bindingId`，
换序不会改变其身份。挂载功能仍只有一条继承行；其他同类行可以删除。
若旧地图有多个候选继承行，先用「设为自带」确认其中一条。

**内容表单**：只读 ID（未创建时显示「未创建」）+ 显示名 + 按 `fields` 声明渲染的字段。
**批量改值（E2）**：本图有多条同功能内容时，表单标题旁出「批量…」——选一个字段（只列
`input`/`choice` 可写字段）、填目标值（复用原字段控件）、先「预览」列出命中/跳过/冲突，
确认后逐条写入。只改已有内容文件，不新建内容、不碰实例绑定；类型不符的文件进冲突，原值保留。
**关系图（E2）**：本功能内容多于一条时出「关系…」——节点按 `(功能 ID, 内容 ID)` 排布，
边读取功能/条件/步骤里声明为 `content:` 的内容引用字段；点节点跳到该条内容，
点边可改接（选目标）或断开（删键，与「未设置」一致），写回走表单同一条内容写路径。
跨功能目标补占位节点，循环引用原样保留；指向不存在内容的引用在提示行计数。
**条件区**：功能声明引用了条件库条目（`conditions: [id, ...]`）时，逐条渲染条件名小节 +
可调字段——与功能字段共用同一份内容 `fields`，同一条件在不同实例上参数各填各的。
游戏还可为功能或步骤声明 `array of condition`：作者按白名单添加可重复条件，
逐行填写参数或取反；放进记录数组后，每条分支可以拥有自己的条件组。
**演出区**：功能声明带 `"steps": true` 时渲染步骤只读摘要 + 「编辑演出」按钮，进入
**演出子面板**：「列表 / 时间轴」两个页签渲染同一份 `steps` 数组 + 当前步骤参数表单
（复用同一套 field widgets 与 choice source）。列表页签：添加/删除/上移/下移/复制；
时间轴页签：条块按 `at/duration/track` 布局，拖块改 `at`、拖右缘改 `duration`、上下拖换轨
（吸附粒度随功能声明 timebase：seconds 0.1 秒 / frames 1 帧 / beats 1/4 拍，负值夹回 0），
松手净化回写（剥掉等于缺省的键）；同轨重叠/负值给 ⚠ 警告
（不改数据）。步骤引用清单 `steps` 池（值=步骤码），步骤参数存在每个步骤自己的 `fields` 里；
未声明的步骤码/参数键只读保留 + ⚠ 提示。
在「时间与轨道」手填时，秒保留输入精度，帧和拍按声明粒度吸附。起点留空恢复同轨顺延，
显式填 0 从零开始。无效数字不会覆盖已保存的值，未修改的显示值也不会因按回车而回写。

声明 `timePreview.audioField` 后，时间轴可从播放头开始试听、暂停、回到起点，
播放中点或拖动标尺可跳听。播放头随音频定位，WAV 支持显示波形概览。
选中步骤后可用「步骤移到播放头」按当前吸附粒度写入 `at`。
参考换算缺项时仍可按原单位编辑；试听不运行游戏事件，关闭或离开时间轴即停止。


**写入时机（逐操作）**：

| 对象 | 内存里是什么 | 什么时候落盘 |
|---|---|---|
| **已落盘**内容的字段 | 直接改文件内容的工作副本 | 控件**失焦 / 回车 / `commit()`** 时即时写该内容文件（不每击键）。写前比对磁盘摘要，外部改过就拒写并提示 |
| **尚未创建**的内容（新绑定第一次改字段） | 暂存行 `_staged[内容ID]` | `Ctrl+S` / 试玩前的统一提交（`flush_staged`）；暂存行只改内存，连撤销栈都不进。绑定被撤销后该行作废，不留孤儿文件 |
| 演出步骤（`steps`） | 与普通字段同一份内容数据 | 同上（同一次写） |
| 实例绑定（`functions[]`、`props` 引用值） | 地图内存态 | `Ctrl+S` / 试玩前的统一提交；改绑定本身进画布撤销栈 |
| 清单（码补发、挂载、资产改名） | 清单内存态 | 保存清单时（含统一提交） |

统一提交顺序固定为 **清单码 → 内容 → 地图**：前一步失败即停，已写部分保留并在 `editor/pending/` 留日志，
下次启动检查是否写全。写盘失败给状态栏 + 右栏红色徽章双重提示，不静默吞掉。
**撤销只覆盖地图**：内容文件改动不进画布撤销栈（改绑定进），删掉绑定的新内容随暂存作废。

**各入口提交哪些文件（唯一规范位置）**：下表是「一次操作写哪些文件」的唯一定义处；
`docs/GAME_SIDE_STANDARD.md` §1 与 `document_commit.gd`／`map_file.gd`／`content_store.gd`／
`recovery.gd` 的模块头只引用本表，不再各自复述文件集合。

| 入口 | 按序写哪些文件 | 提交日志 / 历史 | 代码位置 |
|---|---|---|---|
| 内容视图 Ctrl+S、顶栏「保存」 | ① 清单（仅当有待补发码）② 暂存内容每条一文件 ③ 当前地图（仅当画布脏） | `editor/pending/` 日志；地图写入前快照 | `project_shell.gd::save_current` → `map_file.gd::commit_document` → `document_commit.gd::prepare/apply` |
| 地图菜单「保存」/ Ctrl+S（内容视图同一条） | 同上；无补码、无暂存、图不脏时退化为「无待写改动」 | 同上 | `app.gd::_on_save` → `map_file.gd::save_all` |
| 顶栏「保存」（资产视图） | 只写 `editor/editor_manifest.json` | 无 | `project_shell.gd::save_current` 的 `_` 分支 → `app.gd::_save_manifest_file_async` |
| 试玩 | 同上；提交后地图文件仍不存在则补一次正式保存 | 同上 | `map_file.gd::on_play` |
| 清除悬空引用 | ① 当前图脏则先走整条提交 ② 逐张改动过的地图各写一次 | 第①步同提交日志；第②步每图写前轮转 | `issues_drawer.gd` → `project_audit.gd::apply_ref_fixes` |
| 地图改名 | ① 新名文件写入 ② 旧名文件删除 | 两文件一条日志 | `map_store.gd::rename_map` |
| 复制整图 | ① 新内容 N 份 ② 新地图 1 份 | N+1 文件一条日志 | `map_store.gd::duplicate_map` |
| 内容字段失焦 / 回车 / `commit()` | 单个内容文件（覆盖前轮转） | `.history` 3 轮 | `content_store.gd::write_ex` |
| 内容库「删除」 | 单个内容文件（先轮转再删；轮转失败拒绝删） | `.history` 3 轮 | `content_store.gd::remove_ex` |
| 画布编辑 / 撤销 / 重做 | 不写盘（只改内存） | — | `undo_history.gd` |
| 草稿自动保存（每 2 分钟） | `editor/drafts/<地图码>.json` | 不进历史 | `map_file.gd::maybe_autosave` |

**历史深度（唯一规范位置）**：地图 = `editor/history/maps/<地图码>/` 保留最近 **20 份**
（`recovery.gd::HISTORY_KEEP`，替换成功才计入，失败丢弃快照不减少旧条目）；
内容 = 同目录 `.history/<文件名>.1..3` 共 **3 轮**（`map_store.gd::HISTORY_DEPTH`），
覆盖写与删除前都轮转。两处都是「写得进去才算数」，写不进时内容删除会被拒绝。

### 7.4 资产目录（工作台 →「资产」）

与关卡/内容平级的第三个面板。左列图鉴列表（40px 图标），右侧详情：

| 区块 | 内容 |
|---|---|
| 图鉴名称 | `LineEdit`，失焦/回车写回清单 |
| 自带功能（挂载） | 从顶层 `functions` 声明池挑功能挂为类型自带：实例上显示 🔒 不可删；声明本体属开发契约，这里只挂载 |
| 实例分布 | 按地图分组只读清点该类型全部实例：`id` + 坐标（值在内容编辑器按实例填） |
| 删除此资产 | 先扫全项目引用（哪些地图、多少个实例），有引用需二次确认 |

**实例分布的数据来源**：当前打开的地图**只读画布内存**（新增未保存的会出现、已删除的不残留），
其余地图读磁盘。数值编辑入口只有内容编辑器一个——实例值 = 实例绑定内容（未填 = 声明 default）。
列表为空（含刚删掉最后一个资产）时右栏整体走空态，不留上一项的陈旧控件。

清单写回：剥内部键（`_` 开头、`assets[].atlas_abs`、内置种类）后 JSON 校验再写盘。

**C3–C5 的候选来源**：端口候选读 `assets[].ports`；格图候选读当前图 `meta.cellGraph`
（字段 `source: "cell:"`）；视口候选读清单 `viewports`。端口由游戏侧资产声明提供；
格图可在地图菜单编辑，视口可在项目工作台编辑。声明、下拉与校验使用同一身份。

`source: "cell:"` 字段额外给「画布选…」：选点会话 accept=`"cell"`，命中按格图多边形
（`CellGraph.pick_cell`，多边形是根空间坐标，不走 v7 整数格），悬停/已选在多边形上高亮，
确认后相机对准该格重心再回表单。画布**不叠绘整张格图**，只在选点时会画到光标下的那一格。

### 7.5 项目世界布局

从「地图 ▾ → 编辑项目世界布局…」把现有地图加入布局。左键拖动分块，滚轮缩放、中键平移，
也可用下方字段输入整数像素坐标和范围。保存只提交项目清单。通过「打开地图」继续编辑对应分块的内容；
移出世界不会删除地图。分块身份随地图码，改名后仍可打开，整图复制后需要手动加到布局。
画布显示分块占位与名称，地图文件继续独立载入、编辑和保存。实际游玩时由游戏决定加载和切换策略。
若游戏声明 `worldFrame`，可以点「游戏实景预览…」，按布局画布的取景交由游戏绘制。
预览会包含布局草稿和已加入布局的当前地图工作副本及其暂存内容，其他地图读取正式文件。
程序生成世界可给选中地图填写「生成分块键」，让游戏在该键对应的区域优先使用作者地图。
其余分块由游戏照常生成。重复键会阻止保存；清空键恢复普通分块。
「生成覆盖」可选整块替换、只覆盖瓦片与碰撞差量，或叠加带码摆放物差量。差量模式保留当前种子的基底；
摆放物按稳定实例码添加、删除或修改，未编辑的对象和属性仍由游戏生成。无码摆放物改动需用整块替换。
两种差量都不会覆盖出生点或图层设置。坐标不兼容时布局拒绝新绑定；已绑定地图变得不兼容时，项目自检会提示。

### 7.6 从游戏生成地图

支持生成的项目可从「设置 ▾ → 从游戏生成地图…」选择生成器、填参数和新地图名。
游戏进程返回地图后，编辑器先校验结构并显示尺寸和内容数量。点「打开为可编辑地图」可继续
编辑瓦片、碰撞和实体。它是一张独立的新地图，直到主动保存前没有正式文件；可保存后加入世界布局。

生成地图可用「设置 ▾ → 重新生成当前地图…」恢复上次参数并重跑生成器。
编辑器比较上次生成结果、当前工作副本和新结果，保留双方互不冲突的改动。
发生冲突时显示字段或格坐标和两边的值，可逐项选择保留编辑值或采用生成值。
若投影、格拓扑或基向量发生变化，同时另一边改了空间内容，须先调整参数或地图再重试。
应用前地图保持原样；应用成功后可一次撤销，
保存时沿用原地图码。整图复制或另存转换的副本作为独立地图，不继承生成基线。

## 8. 试玩集成

清单可启用「试玩项目」，无需打开地图即可启动独立任务、剧情、节奏或界面入口。
游戏声明可试玩的入口功能后，项目内容库可对该类型的独立内容使用「试玩所选内容」。
这只指定本次试玩的起点，工作台的「试玩项目」仍走游戏默认入口。
游戏接入加载回执后，状态栏会区分加载成功、版本不符、加载失败和未返回结果。
「最近试玩反馈」显示游戏可选返回的作者反馈。游戏运行中重新打开窗口即可读取最新回执。
含内容定位的反馈可直接打开指定演出步骤；
若内容在试玩后已修改，需重新试玩才能定位。
作者流程测试从编辑器启动单独的 Godot 游戏进程，验证项目入口和有向格图两条路径。

| 功能 | 说明 |
|---|---|
| 试玩命令 | 优先用清单结构化配置 `playtest.executable` + `playtest.args`（直启、参数按数组传，空格路径无需转义；可执行文件不存在时提前报错）；否则退回 `playCommand` 模板 + `%mapfile%` / `%projectpath%` 替换（经 `cmd /c` / `sh -c` 执行） |
| 可移植可执行文件 | 清单可选 `godotExe`（支持 `%projectpath%`）覆盖命令里的可执行文件，换机器不必改 `playCommand` |
| 自动引号 | 占位符替换值含空格且模板未加引号时自动补引号 |
| 可执行文件检查 | 首参是路径且文件不存在 → 提前报错，避免 `cmd /c` 假成功 |
| 保存前置 | 试玩前先走统一提交（清单码 → 内容 → 地图），提交失败即中止；新建未落盘的图再补一次正式保存 |
| 项目内路径守卫 | 试玩只接受 `maps/` 目录内的路径，越界拒绝启动 |
| 进程跟踪 | 直启时跟踪的 pid 就是游戏本体；走 `playCommand` 模板时跟踪的是 `cmd /c` 包装进程（状态栏会说明）。`OS.is_process_running()` 系统调用，1 秒节流，启动后 4 秒内不判死，退出时报「运行 N 秒」；除 web 导出外均可跟踪 |
| 日志尾随 | 退出时读 `<项目>/editor/playtest.log` 最后 4 行一起报 |
| 试玩配置 | 弹窗由清单 `playtest.flags` / `playtest.params` 声明驱动渲染（flags → 勾选框启用时原样追加 arg；params → 数字参数，值 ≠ def 才追加）；值存 `user://playtest_prefs.json`，按地图独立，不写进地图 JSON；清单未声明 = 面板空态提示 |
| 启动参数 | 追加声明里的 `arg`；带出生点参数时追加 `--spawnx/--spawny`（格坐标） |

试玩配置在切换地图时自动跟随该图（`_sync_play_cfg_to_map`）。

| 撤销 / 重做 | `Ctrl+Z` / `Ctrl+Y`（`Ctrl+Shift+Z` 同效） |
| 剪贴板 | `Ctrl+C` 复制 · `Ctrl+V` 粘贴 · `Ctrl+X` 剪切 · `Ctrl+D` 原位复制 |
| 编辑 | `Del` 删除选中 · `F` 水平翻转 · `R` 旋转 90° / `[` `]` 缩放（实体；瓦片笔刷下 `R`/`X` = 笔刷旋转/翻转）· 方向键微调 1 格（`Shift` = 4 格） |
| 文件 | `Ctrl+S` 保存 · `Ctrl+N` 新建 · `Ctrl+O` 打开 |

**键盘入口唯一在 `app._shortcut_input`**：画布在 `SubViewport` 里收不到键盘。
输入框（`LineEdit` / `TextEdit`）获得焦点时全部画布快捷键放行；项目页（内容/资产）只接管
`Esc` 与 `Ctrl+S`，其余键交给视图内控件。

### 9.2 交互约定

- **左键 = 放置/涂刷，右键 = 擦除/删除**，语义由**选中的资产**决定（place_kind），没有工具要选。
- **框选开关**在状态栏右侧（不是快捷键）；打开后左键拖动 = 框选，关闭回到涂刷/放置，
  此时 `Ctrl+拖动` 仍可作为框选入口。
- 网格开关也在状态栏右侧；未保存徽章、光标坐标、当前层与笔刷信息常驻状态栏右侧。
- `Alt+左键` = 吸管，从顶层向下取光标格瓦片为当前笔刷（吸到哪层切到哪层；不吸实体、不吸碰撞）。
- 未打开地图时禁用全部编辑交互。

### 9.3 界面结构

```
┌ 顶栏：项目名 │ 设置▾ │ ───── │ 地图▾  [关卡][内容][资产] │ ─ │ 试玩配置 · ▶试玩 ┐
├──────────────┬──────────────────────────────────────────────────────────────┤
│ 左栏 200px   │ 画布（SubViewport，吃满剩余宽高）                            │
│ 层：… ▾      │                                                              │
│ ─────────    │  ┌ 选中信息条（浮在画布下沿，仅选中时显示）┐                 │
│ 资产列表     │                                                              │
│ （按层切换） │                                                              │
├──────────────┴──────────────────────────────────────────────────────────────┤
│ 状态栏：操作消息（左，撑满） │ 框选 · 网格 · 层/笔刷 · 光标坐标 · 未保存 · ? │
└─────────────────────────────────────────────────────────────────────────────┘
```

- 画布上方**没有横带**；编辑工具与剪贴板按钮一概不在顶栏。
- 左栏只决定「给画布喂什么」：层下拉 + 资产列表。
- **内容 / 资产面板**共用 `project_shell` 外壳：顶栏（标题 + 项目徽章 + 同一套 `TopBarNav` + 保存）
  + 内容区 + 状态栏；`Esc` 回画布，`Ctrl+S` 按当前视图分派保存目标。
  `app._set_status` 按当前视图分派到对应那条状态栏（关卡一条、项目页一条，隐藏的那条写了等于没写）。
- **弹窗**统一走 `_popup_body` / `_open_popup`：按内容最小尺寸居中并夹回可视区；
  内容宽度固定 `POPUP_BODY_W = 340`，换行标签必须显式给宽度（否则 Label 宽度被测成接近 0、
  高度爆成几十行，把弹窗撑到一屏）。
- **空状态**：未开图时画布中央给引导；资产列表/内容列表为空时都是图标 + 主文案 + 下一步提示。

### 9.4 撤销与缓存

- 撤销栈上限 80 步，支持差量和整图快照：
  1. 瓦片/碰撞的涂刷与擦除存**笔画差量**（`{kind:"delta", cells:[{kind,layer,cell,before,after}]}`，
     一次手势一条，undo/redo 双向复用同一份差量）；
  2. 实例新增/删除/编辑存**实例差量**（`{kind:"ents", ops:[{op:"add"|"upd"|"del", key:<实例码>,
     before:<行>|null, after:<行>|null}]}`）——`key` 就是 `InstanceKey` 的可寻址部分（地图码由
     撤销栈自身所属文档隐含）；`before`/`after` 用与地图落盘同一份行口径（`_object_row`），
     undo 只按这几条重建/改写/删除节点，图上其它实例一个字段都不动；
  3. 内容字段与改名存**内容差量**（`{kind:"content", fn, cid, before, after, digest_before,
     digest_after}`）——`(fn, cid)` 就是 `ContentKey`；undo 只写回那一个内容文件，且盘面摘要
     与记录不符（被别人改过）时**拒绝回滚**并提示，不拿记忆里的旧值覆盖别人的工作；
  4. 跨层搬动的一步差量包含源格和目标格的变更、带码实例的位置、搬动的格图行和出生点；
     撤销和重做直接写回现有地图和实例。搬动无码场景图片时使用整图快照。
  5. 格图编辑只保存修改前后的格图，撤销和重做不会重建瓦片或实例。
- **没有实例码的目标**（场景图片，`shape: image`）不能用差量寻址，仍走**整图快照**
  （JSON 字符串）。全局操作（尺寸/层/粘贴整块区域/转换投影）也仍是整图快照。
- 瓦片批量替换只记录受影响的格，保留图集变换位。任一待写格所在图层被锁定时，整次替换停止；
  不涉及的图层即使锁定也不影响操作。
- 自动生成碰撞只记录变化的碰撞格，一次生成对应一个撤销步骤。替换模式的撤销可恢复旧碰撞形状、
  类型和游戏自定义字段；相同结果重复生成不会新增撤销步骤。
- 内容视图里 Ctrl+Z 只撤内容条目（`undo_content_only`）：栈顶是地图改动时不认领、不吞键。
- 方向键微调：1 秒窗口内连续微调合并成**一条**实例差量，撤销回到窗口起点。
- 撤销恢复走 `load_data(keep_dirty=true)`（快照条目）或就地写回（差量条目）；图层锁定状态保留；
  **恢复期间 undo/redo 互斥**（快照恢复是异步的，让帧重建；两个恢复流交错会弹错快照、画布被双重覆盖）。
- 涂刷/擦除是**笔画制**：按下开笔画（`stroke_begin`），首个真实改动记进差量（`stroke_touch_*`），
  抬手定格成一条 `delta` 条目；点一下空白不留撤销步。
  笔画途中若命中实例删除（右键擦到实体），先定格当前笔画再记一条实例差量——两种条目各自成步，undo 逐步回退。
  拖实体或出生点若未改位置，不产生历史条目。
- 派生缓存与失效点：

| 缓存 | 键 / 触发 | 失效方式 |
|---|---|---|
| 实体 `by_id` 索引 | 画布实体集 | `_mark_ents()`（只置实体脏）/ `_mark()`；瓦片与碰撞写入走 `_mark_tiles_layer(li)` / `_mark_collision()`，不碰实体索引 |
| 三角瓦片自绘 | 单层瓦片数据 | `_mark_tiles_layer(li)` 只重画被写的那一层；`_mark_tiles()` 全层（撤销跨层差量之外的兜底路径） |
| 「这层有没有瓦片」 | 层下标 | `layer_has_tiles(li)` 一次 `used_cells` 扫描后缓存；瓦片写入（`_mark_tiles*`）与层栈重建时失效 |
| 悬停重画闸 | 上次悬停格 / 像素点 / 框选组热区 | 无手势时只在换格、进出热区或位移 ≥ 2px 才重画（手势中逐帧跟手） |
| 右栏表单控件 | 实例码+类型+props+绑定+展开功能+内容数据+定位字段 的签名 | `content_editor._rebuild_right` 签名不变直接留用现有控件（保住焦点/滚动/未提交值） |
| 实体引用集 | `MapStore.project_rev` | 任何 `write_text` 成功即 `rev+1`；换图时显式 `invalidate_ref_cache()` |
| 实体缩略图 | 清单目录 + `project_rev` | 随 rev 变化重建 |
| TileSet / 图集纹理 | 图集路径 + `tileSize` + 各图集 mtime | 外部改图集后自动重建 |
| 地图读缓存 | 文件 mtime + size | 写盘时 `_cache.erase(path)`；浏览口径的缓存。外部工具若在**同秒且同长度**改写地图，缓存可能命中旧结构——需要最新盘面时用 `MapStore.invalidate_read_cache()` 人工刷新（破坏性操作前已自动调用） |

## 10. 校验

两套静态校验，都是「issue 列表」形状 `{severity, path, message}`：

### 10.1 清单校验（`manifest_validation.gd`，读清单时执行）

| 检查项 | 级别 |
|---|---|
| `assets` 不是数组 / 资产 `id` 空或重复 / `kind` 不在 `scene`/`entity` | 错误 |
| `functions`·`conditions`·`steps`·`audio`·`triggers` 不是数组或对象 / `tileSize` 非正数或 `[w,h]` 非两正数 | 错误 |
| 清单出现 `tiles` / `entities`（已并入 `assets[]`） | 错误（跑 `tools/migrate_project.gd`） |
| scene: `shape` 给了但不在 `tile`/`image`（缺键缺省 `tile`）/ `atlas` 与 `texture` 恰好给一个 / `atlas` 为空或含 `..` / 调色板条目缺 `cell` / `gridProjection` 取值非法 | 错误 |
| entity: 声明了 `shape`（实体无形状）/ `prefab` 与 `visual` 都没有 / `visual` 不是对象或 `visual.type` 不在 `rect`/`poly`/`path`（缺省 `rect`）/ `editorSize` 形状非法 / `fields` 非数组 | 错误 |
| 资产 `code`（`kind=entity`）重复 | 错误 |
| 实体挂载了未声明的功能（实体字段**不查 kind**，kind 只约束功能/条件/步骤声明） | 错误 |
| 功能/步骤/音频/时机**条目码**池内重复；**字段码跨池/跨功能同码**（三池一个码空间）报错 | 错误 |
| 字段 `type` 不在 `string`/`int`/`float`/`bool`/`color`/`vector2`/`range`/`asset_ref`/`array`/`port_ref`/`viewport_ref`/`edge_ref` | 错误 |
| 功能/条件/步骤/音频/时机 id 空或重复（数组写法）/ 步骤条目（dict 写法值）不是对象 / 功能 id 不是合法内容目录名（只允许字母/数字/`_`/`-`，**不允许点号**，与 `ContentStore.is_valid_kind` 同规则） | 错误 |
| 功能引用未声明的条件 | 错误 |
| 功能 `triggers` 不是数组或引用未声明的时机 / `timing` 不是对象或 `timing.mode` 不在 `instant`/`duration`/`continuous` | 错误 |

## 12. 已知边界

- 跨图引用写地图码（`meta.code`）：图改名不影响引用；旧图引用值存图名的，跑迁移脚本重映射。
- 自动草稿整图覆盖写、不做多版本；草稿不自动载入，打开项目时由提示条询问。
  正式保存另有 `editor/history/maps/<地图码>/` 快照；内容文件有同款 `.history`（两份深度见 §7.3「历史深度」）。
- 撤销是**混合粒度**（条目见 §9.4）：瓦片/碰撞笔画、实例增删改、内容字段及带码实例的跨层搬动只记录受影响的数据；
  整块区域粘贴、层参数与尺寸这类改动仍存整图快照——
  大图（数千格 + 数百实体）连续做全局操作仍有内存与耗时成本（10 万瓦片一次快照约 140 ms）。
- 校验只做静态数据检查，不验证运行时可达性（例如落点是否在实心碰撞里）。
- 试玩**启动**按平台分支（Windows 走 `cmd /c`，其它平台走 `sh -c`）；**进程跟踪**走 `OS.is_process_running()` 系统调用，除 web 导出外均可跟踪；web 导出无法查询进程，状态栏明示「此平台无法跟踪进程退出」，不假装仍在运行。
- `trigger_zone`（事件）的 `w/h` 用画布右下角把手拖拽调（R-04）；触发语义在绑定的 `functions[]`（timing + 时机码）。
- 不做瓦片自动拼接（autotile）；碰撞自动生成是辅助功能，生成后仍可手改。
- 无图集编辑器入口；新增瓦片组需要直接改清单。
- 只在格对齐意义上吸附（吸附默认开）：关掉后可放在任意像素位置，存浮点格坐标。
  旋转/缩放走画布手势（`R` 90° 步进 / `[` `]` 缩放步进）；`F` toggle 水平翻转。
- **地图数据**写盘只有一条路径：`editor_canvas.extract()`（prefs/清单/内容文件各走各的入口）；
  游戏侧 `MapLoader` 只读，不反向写回，避免格式分叉。
- 内容系统只做「绑定 + 内容字段编辑」，功能行为完全在项目侧；编辑器不校验内容语义。
- 时间轴只做条块摆放（at/duration/track）：时间基随功能声明（`timebase: seconds/frames/beats`——
  帧级数据 = frames 基的步骤数组，格斗 hitbox/谱面音符按声明帧/拍摆块）；不做关键帧曲线、嵌套时间轴、音频波形。
- 等距（`gridProjection: isometric`）画布已全对齐：网格线/幽灵/选区框/实体锚点换算走 GridSpace 格原语（菱形口径）；
  斜坡碰撞可视化按菱形包围盒近似。内容编辑器中列预览（R19）**地形**已走同一套格多边形+切片 UV（含 `alt`），
  网格线与实体落点也按生效格空间算；层的 `offset`/`scale` 在预览里同样作用于地形与实例（同一 `MapViewData.layer_transform`，
  两处不再各算一套）；仍简化的是：预览不分层配色的细节、层混合模式在预览里不挂材质。
  PNG 导出同样按 `offset`/`scale` 扩边界与落位（`parallax`/`ySort` 不参与——它们只影响运行时相机与遮挡顺序）。
- 六边形（`gridProjection: hexagonal`）画布同样全对齐（odd-r 错行 + 尖顶，与 Godot 默认
  HEXAGON/STACKED/HORIZONTAL 逐位一致，探针实测）：命中 = 最近中心 Voronoi，格线 = 行界折线 + 行内竖边；
  区域/笔刷/地图边界外框按四角 cell 包围盒近似。
- 格尺寸（`tileSize`）可声明 `[w,h]` 矩形格：全部格对齐换算走 GridSpace（tile Vector2 口径），
  画布/幽灵/预览/缩放拟合/热区容差自适应；等距 2:1 菱形、六边配矩形格同走各自公式。
- 三角格（`gridTopology: "triangles"`）已接通画布：拾取按半格对角线、邻接三边、网格线 = 方格 + 对角线，
  瓦片由 `TriTileView` 自绘（TileMapLayer 表现不了半格三角形，数据层常隐但仍是六元组真源）；
  图层显隐同时作用于自绘层。斜平面（`gridBasis`）走了同一格原语。
  项目参考视图支持图片和内容热点；与地图空间联动的伪 3D 或并排视图仍需游戏侧提供区域映射契约。
- 层参数（parallax/ySort/offset/scale/blend）由画布直接预览；层管理弹窗每层带参数行
  （y排序开关 + 视差/偏移/缩放数字字段，回车提交，缺省整键省略）。
  碰撞自动生成不区分声明形状（按整格矩形推）。
- 排序点（`sortAnchor`）实例选中时画排序点十字（锚点 + sortAnchor 像素偏移，紫十字 + 连线；无覆盖不画）。
  排序点不移动轮廓、路径、顶点手柄或端口；这些都使用同一个实例数据锚点。
- 资产零登记扫描制：文件放进约定目录（`assets/tiles|images|entities`，递归；图片 png/jpg/jpeg/webp/bmp/tga、
  实体 .tscn）即资产，打开项目扫描自动补条目 + 发 4 位资产码（id=码、name=文件名 stem）；
  改名按持久化指纹（`scanFingerprint`）一对一重链原条目（候选歧义进待确认，不猜）；消失标停用不删条目
  （可恢复），约定外手写条目不碰；
  细配置（palette/cell/锚点/挂载）仍走清单条目覆盖，扫描只补骨架不改写已有条目。
- 几何段（R-02）：实体声明 `visual: {type: "poly"|"path", color, alpha, closed, width, points}` 即几何对象——
  画布按声明画填充多边形/折线，顶点拖拽/双击加点/右键删点写 `props.points`
  （[[x,y],…] 像素相对锚点，翻转后存取仍走未翻转局部系）；游戏侧读 `objects[].props.points` 透传。
  离格自由摆放本就支持（吸附关 = 浮点像素位置）。
- 问题抽屉：展开即自动重扫（条目永远新鲜）；悬空引用条目带「清除悬空」一键擦掉悬空字段值
  （字段留空=未填；当前图有未保存修改时跳过该图；写回前的快照在 editor/history/maps/<地图码>/）。
- 保存前外部改动预警（C-20）：地图与清单在编辑器打开后被外部改过时，保存先弹确认框
  （覆盖保存 / 取消保留外部改动）；自动草稿不受影响（写的是另一个文件）。
- **端口和参考视图**（C3/C5）：本图端口可在实例、功能或步骤的引用字段中用「画布选…」点选；
  在摆放画布选中实例后，可拖动端口字段把手到兼容端口以接线或改接；松在空地断开、右键取消，修改可撤销。跨图端口可从目标图下拉选择，也可在目标图的已保存实景点选。参考视图支持热点叠层和点选；
  连接语义和运行时行为归游戏侧。格图编辑器显示多边形与有向出边；可拖顶点、
  Shift + 单击边插点、右击顶点删点，也可切换连边模式后点选出边目标。坐标和邻接表单仍可精确输入。
  需要通行代价、条件标签等参数时，用「新建连接」创建独立有向边。边可重接、可并行；
  参数控件来自游戏清单的 `cellGraphEdgeTypes`，蓝紫色连线表示独立边，选中后高亮。
  可以从「目标地图」和「目标格」建立跨地图连接，改名后仍按地图码定位。项目自检会定位悬空目标；
  预览显示选中跨图边的出口标记和目标身份。在预览中点格重接会把目标改回当前地图。
  「添加空间」可设定楼层或视角的原点和两条基向量，再为格选择所属空间。可只看一个空间，
  也可显示全部空间后点选跨空间的连接目标。切换格的空间会保留其局部顶点数值；拖点会自动换算。
  空间可绑定地图图层，预览与主画布使用该层的位移和缩放，主画布高亮与拾取也跟随视差。
  图层管理可给空瓦片层选择独立正交、等距、六边或三角格，也可输入双基生成斜平面四边格或三角格。
  随后该层可按自己的格系涂画、拖刷、擦除、吸管取样和生成格图；
  实例、出生点和根碰撞仍使用地图格系。独立瓦片层使用自绘，瓦片不会逐片参与实例 Y 排序。
  混用格系时，瓦片框选只作用于选区所属层；支持复制、剪切、移动和批量替换，并可粘贴到同格几何的瓦片层。
  若要同时搬动不同格系的瓦片、实例和根碰撞，使用状态栏「跨层搬动」。已有瓦片的层可在图层管理中迁移瓦片，
  按原格号或源格的局部像素中心生成新瓦片层。检查会列出越界和重叠；有冲突则整批不写。
  新层继承源层显示参数，源层 ID、原瓦片、实例、根碰撞和格图绑定保持原样。生成新层可一次撤销。
  有铺好的规则格地图时，可在格图弹窗选择瓦片层，输入新空间 ID，再点「从瓦片生成格」。
  有画布框选时默认只导入其中的格号，可取消限制；每批最多 2048 格。生成格跟随该层，批次内的共边格自动双向相连。
  生成结果是可独立编辑的快照；瓦片与碰撞不会同步改变格图。生成只使用有瓦片的格，需要禁行的格或边请在格图中处理。
  再次导入可补齐新瓦片；已有生成格保留原状，和手工格 ID 撞名则中止本批。勾选「连接相邻旧格」时，
  新格与同空间、同格几何且仍有瓦片的相邻旧格补双向边，允许跨框选边界；旧格之间的边不变。
  跨图层、跨地图或有通行条件的连接仍可用独立有向边。
  删除绑定图层时保留格的静态位置和连边，一次撤销即可恢复原图层和绑定。
  在地图主画布上，`cellGraph` 只在 `source: "cell:"` 字段点「画布选…」时
  按多边形命中并高亮光标下那一格（不整张叠绘、不画格边）。
- **撤销的多种粒度不互相合并**（B4）：一笔涂刷 = 一条格差量，一次实例增删 = 一条实例差量，
  一次内容改值 = 一条内容差量；只有方向键微调在 1 秒窗口内合并实例差量（相同实例集）。
  不同粒度的条目混在同一栈里按时间倒序回退，不折叠——一次手势里有涂刷又有实例删除就是两条。
