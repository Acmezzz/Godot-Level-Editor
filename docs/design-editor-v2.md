# 编辑器 v2 设计（三面板 / 功能绑定模型）

> 日期：2026-11-18
> 状态：设计契约，待实施
> 配套演示：`docs/demo-editor-v2.html`（单文件，可点：三面板切换 / 层下拉 / 选实例 / 库复用 / Esc 逐级返回）

---

## 0. 一句话模型

**画布是唯一载体。地形/背景/碰撞是无行为能力的摆放物，实体是有行为能力的摆放物。
实体类型有删不掉的固定功能（只能调参），实例还能挂任意通用功能。
参数和内容本质相同——都是给已有功能逻辑填值。**

由此得出三个否定：

- **否定工具概念**：没有涂刷/矩形/盖章/擦除工具。层决定行为，左键放置、右键擦除。
- **否定检查器**：它不是面板，只是「填了没有」的校验。
- **否定内容种类预设**：没有「对话/事件/商店/定义」四种既定类型；功能由项目侧代码声明，编辑器只填。

## 1. 三个并列面板

三个面板是**平级**关系，不是父子视图。全局横带左侧三个入口，当前项高亮，Esc 回上一个。

| 面板 | 职责 | 动词 |
|---|---|---|
| 关卡编辑器 | 把资产摆到地图上并定位 | 摆放 |
| 内容编辑器 | 给实例挂功能、填功能内容 | 编排 / 填写 |
| 资产目录 | 查图鉴；改类型默认参数；看实例分布并改实例参数 | 查阅 / 调参 |

切换成本必须低：日常在关卡编辑器，写内容去内容编辑器，查资料去资产目录。

## 2. 关卡编辑器（只摆放）

### 2.1 骨架

```
┌─ 全局横带：项目名 │ 地图名 ▾ ────────────── [关卡][内容][资产] ▶试玩 ┐
├─ 左栏 200 ─┬─ 画布（占满剩余） ───────────────┬─ 无右栏 ─┤
│ 层下拉 ▾   │                                    │          │
│ 资产列表   │                                    │          │
├────────────┴────────────────────────────────────┴──────────┤
│ 状态栏：消息 │ 网格 背景 │ 坐标 · 层 · 未保存 │ ?           │
└─────────────────────────────────────────────────────────────┘
```

右栏整体消失，画布获得全部剩余宽度。这是 1366 宽下不再溢出的根本解法。

### 2.2 层决定一切

左栏只有一个控件决定输入：**层下拉**。

- 下拉项 = 全部层（地形 / 装饰 / 碰撞 / 实体 …），**包含实体层**。
- 选中某层 → 资产列表自动换成该类资产（现有 `editor_state.gd:_sync_ui()` 已实现此联动，保留）。
- 层类型决定画笔行为，**不再有工具概念**：

| 层类型 | 左键 | 右键 |
|---|---|---|
| 地形 / 装饰 / 碰撞 | 按住拖动连续涂 | 拖动擦除 |
| 实体 | 单击放置当前位置选中的资产 | 单击删除该实体 |

- 显隐 / 锁定内联在**下拉项**里，每项两个小开关（不占额外高度、不开第二个面板）。
- 删除现有的「地形瓦片 / 实体」两个页签按钮——它们是多余的第二套切换。

### 2.3 选中实体

只显示一条**极小信息条**（画布角落或悬浮于选中框上方），内容为：

```
[类型名] [有无内容标记] [在工作台编辑 →]
```

不做属性表单。参数属内容，归内容编辑器与资产目录。

### 2.4 地图级入口

全局横带左端的**地图名本身就是下拉按钮**（`TEST ▾`），点开容纳全部地图级动作：

- 新建 / 打开 / 保存（现有；保存旁标 `Ctrl+S`）
- 导出当前地图 / 调整地图尺寸 / 选择背景图组（现有，从工具条移入）
- **关卡清单与世界拓扑**（自项目页「清单」迁入；原 Q41 决策）

这样全局横带在任一宽度下都只有「项目名 · 地图名 ▾ · 三个面板 · 试玩」四组东西，不再有随宽度挤出可视区的风险。

### 2.5 快捷键（最终清单）

| 键 | 作用 |
|---|---|
| Ctrl+Z / Ctrl+Y | 撤销 / 重做 |
| Ctrl+C / Ctrl+V / Ctrl+X | 复制 / 粘贴 / 剪切 |
| Del | 删除选中 |
| Ctrl+S | 保存 |
| Esc | 返回上一个面板 / 取消当前操作 |
| ? | 快捷键速查 |

**删除全部数字键与工具键**（1-6）。它们从未是用户设计的一部分，是历史实现遗留。

## 3. 内容编辑器（给实例挂功能、填内容）

### 3.1 骨架

```
┌─ 全局横带：项目名 │ TEST ▾（含地图切换 + 未填徽章） ─ [关卡][内容][资产] ▶试玩 ┐
├─ 左：本图实例 ─┬─ 中：画布预览（只读） ─────┬─ 右：实例与功能编辑 ──┤
│ TEST 实例 1/3  │                          │ 商人  TEST.e_3        │
│ 商人      e_3 ●│      （点击实例选中）      │ 固定功能：           │
│ 小怪      e_5  │                          │   生命 ▮ 伤害 ▮       │
│ 传送门    e_9  │                          │ 附加功能：           │
│ 只看未填 (1)   │                          │   ① 对话  [问好] ▾    │
│                │                          │   ② 商店  [未填] ▾    │
│                │                          │   + 添加功能 …        │
└────────────────┴──────────────────────────┴───────────────────────┘
│ 状态栏                                                          │
```

三个区域常驻，不切页。**地图是全局状态，在顶栏切换**；左列只列当前地图的实例。

### 3.2 左列：当前地图的实例列表

- 标题行：`<地图名> 实例` + **未填计数徽章**（`1/3 未填` = 3 个实例里 1 个还有功能没填）。
- 每行：类型名（`商人`）+ 实例 id（`e_3`）+ 行尾状态点（黄 = 有未填功能，绿 = 齐了）。
- 点行 = 选中，与画布点实体同步；点画布实体也高亮对应行。
- 底部「只看未填 (n)」就地过滤本列表——这就是 Q25/Q31 的校验清单，不另设页面。
- 切地图（顶栏下拉）→ 左列实例、画布、右列全部跟着换。

**为什么地图切换在顶栏而不在左列**：地图是全局状态，关卡编辑器也用同一个当前地图；把它放内容面板左列会让「当前地图」出现两个真相来源，切换后关卡编辑器还得同步。放顶栏后，未填徽章挂在每个地图项上，Q31 的「按地图分组 + 徽章」依然成立。

### 3.3 中列：只读画布预览

- 复用关卡编辑器同一套渲染，禁用全部输入；点击实例 = 选中。
- 不做视觉标记区分「有内容/无内容」。理由：很多实体（如小怪）只有固定功能，本就不需要额外内容，标记会造成噪声（原 Q19 决策）。

### 3.4 右列：实例与功能

分两段：

1. **固定功能**：类型自带的参数（血量、攻击、传送目标…），只能改值。
2. **附加功能**：可增删的通用功能列表。

附加功能列表的每一行：

```
① 对话        [问好]      ⟳ 并行  ✕
```

- 序号 = 执行顺序。
- 名称 = 当前绑定的内容条目名（未绑定显示「未填」）。
- 「并行」勾选 = 与前一项同时触发。
- 点击该行 → 展开该项的内容表单（在列表下方就地展开，或右侧换内容区）。

**复用的入口在这一行内**：功能行上的「库」按钮，点开列出同功能的全部已有内容，选一条即**复制**进当前实例（生成新 ID，名字可另起）。

### 3.5 功能模型

**三种东西必须分清**：

| 概念 | 归属 | 谁定 |
|---|---|---|
| 功能有哪些、要填哪些字段、触发时机 | 项目侧代码 + 开发标准 | 游戏代码 |
| 功能间的顺序 / 并行 | 编辑器 | 作者 |
| 功能内部逻辑（对话可循环还是一次性） | 项目侧代码 | 游戏代码 |

- 编辑器只编排**顺序与并行**；并行 = 与前一项同时触发。
- 「循环 / 一次性」这类是功能内部逻辑，由项目侧暴露为可填项或直接写死，编辑器不感知。

### 3.6 功能声明（开发标准）

功能声明**不是**编辑器可自由创造的东西，而是开发标准的一部分：

- 项目侧实现功能后，在清单中声明该功能的可编辑字段（与实体 `stats`/`fields` 同构）。
- 编辑器只读这份声明，据此渲染表单与功能下拉；**不提供在编辑器内新增/修改声明的入口**。
- 声明是契约：编辑器能列出的功能，必然是游戏侧已实现的。示例项目阶段可直接改 JSON。

现有 `manifest.gd` 的 `fields` / `stats` 机制即为这种「声明 → 动态表单」的既有实现，功能声明沿用同一思路。

## 4. 资产目录（图鉴 + 调参）

独立并列面板，**不只是查阅**。现有 `asset_panel.gd` 已是这个形态，保留其结构：

| 现有实现 | 保留 / 调整 |
|---|---|
| `show_quick()` 快速总表（6 列数值直改） | 保留 |
| `show_detail()` 图鉴详情（名称/数值模板/字段定义） | 保留 |
| `_add_distribution_section()`（:373）实例分布 | 保留；每实例一行可**跳转定位**并**改该实例参数** |
| `_add_size_row()` editorSize | 保留 |

与内容编辑器的分工：资产目录按**类型**看，内容编辑器按**实例**看。同一实例的参数，两处都能改，但入口语义不同——资产目录是「这个类型有多少个、分布在哪些图」，内容编辑器是「我正在写这张图的这个实例」。

## 5. 数据模型

### 5.1 ID 规则（分层，短随机码）

ID 供游戏使用；名字（`name`）供人阅读。两者分离。

| 层级 | 形态 | 示例 |
|---|---|---|
| 地图 | 现有地图文件名 | `TEST` |
| 实体类型 | 现有清单实体 id | `merchant` |
| 实例 | 地图前缀 + 序号（现有 `e_N` 沿用或改前缀） | `TEST.e_3` |
| 内容条目 | 地图-实体-实例-功能-短随机码 | `TEST-merchant-e_3-dialogue-7K2QX9` |
| 内容条目（跨实例复用时） | 同上，仅换随机码 | `TEST-merchant-e_7-dialogue-M4PZ1A` |

**关键规则**：复用 = 复制内容 + **生成新 ID**。库中每条内容都是独立条目，不存在「两条记录指向同一 ID」。

### 5.2 内容存储

按功能分目录（原 Q36 决策）：

```
<项目>/content/
  dialogue/<id>.json
  shop/<id>.json
  ...
```

- 每个条目一个文件，文件名即内容 ID。
- 条目内 `function` 字段标明所属功能，`name` 为作者起的名字。
- 新增功能时自动出现新目录——目录由功能声明驱动，不是硬编码白名单。

对比现状：`content_store.gd:10` 的白名单 `["defs","dialogues","events","shops","schema"]` 需移除，改为按清单 `functions` 声明推导。

### 5.3 实例绑定

地图文件内实例新增 `functions` 数组：

```json
{
  "id": "TEST.e_3",
  "scene": "merchant",
  "props": { "hp": 3 },
  "functions": [
    { "fn": "dialogue", "content": "TEST-merchant-e_3-dialogue-7K2QX9", "name": "问好", "order": 1, "parallel": false },
    { "fn": "shop",     "content": "TEST-merchant-e_3-shop-B2N8WD",      "name": "杂货", "order": 2, "parallel": false }
  ]
}
```

- 绑定写在实例上（原 Q42 决策）；内容单独存文件。
- `props` 保持现有语义（固定功能的实例级覆盖值）。
- 旧的 `def` 字段过渡期内保留读取，写入统一走 `functions`。

## 6. 窗口分档

| 宽度 | 关卡编辑器 | 内容编辑器 |
|---|---|---|
| ≥1440 | 左栏 200 + 画布 | 左 220 + 中画布 + 右 360 |
| 1200–1440 | 左栏 200 + 画布 | 左 200 + 中画布 + 右 340 |
| <1200 | 左栏收成 48px 窄条，点击展开 | 左列收成 48px 窄条，中右保比例 |

原则：**左列（层与资产入口 / 本图实例）让步，右列（当前工作区）不让步**。理由见原 Q33——左列是「选一次、用很久」的低频操作。

分档只在 <1200 才真正收窄：删掉右栏与内容抽屉后，1366 宽下内容编辑器实测已无溢出（三列 200 + 画布 828 + 340），不需要提前收窄。窄条档保留为兜底。

## 8. 实施批次

### 批次 A：关卡编辑器瘦身（零数据风险）

先做，因为它只删 UI、不碰数据，能最快验证「没有工具概念」是否真的顺手。

1. 删工具组、剪贴板按钮、上下文条、两个页签按钮、竖向图层列表。
2. 层下拉接管：资产列表联动（已有）+ 显隐/锁定内联。
3. 删右栏检查器；画布占满。
4. 工具条改为单一「地图 ▾」+ 视图开关归状态栏。
5. 删数字键与工具键，`shortcut_test` 同步改。

验收：1366 宽下无溢出；涂刷/擦除/放置全部只靠层 + 左右键完成。

### 批次 B：数据层（统一内容模型）

1. 移除 `content_store.gd` 的 KINDS 白名单，改为按清单 `functions` 声明推导目录。
2. 实现分层 ID 生成（地图-实体-实例-功能-短随机码），碰撞时重试。
3. 实例 `functions` 数组读写 + 旧 `def` 字段过渡读取（写入只写新字段）。
4. 功能声明读取与字段渲染（与 `fields`/`stats` 同一套）。
5. 迁移示例项目现有四类内容数据到 `content/<功能id>/`。
6. `MapValidate` / `ContentValidate` 适配新结构（出口后续换到内容编辑器）。

验收：旧界面（含内容抽屉）在新数据上行为不变；示例项目四类内容一条不少。

### 批次 C：内容编辑器

1. 三区壳（左本图实例列表 + 未填徽章与过滤 / 中只读画布 / 右实例与功能）。
2. 固定功能参数段 + 附加功能列表（序号 / 名称 / 并行 / 删除）。
3. 功能内容表单（按声明渲染）。
4. 「库」按钮就地复用弹窗（复制成新 ID，名字可另起）。
5. 顶栏地图下拉承载切图与未填徽章；左列实例与画布点选双向同步。
6. 删除内容抽屉挂载点（功能已迁入内容编辑器）。

验收：示例项目里能完整走一遍「选地图 → 点实例 → 加功能 → 填内容 → 复用一条已有内容」。

### 批次 D：资产目录与收尾

1. 资产目录改为并列面板入口，保留总表/详情/实例分布。
2. 实例分布行支持「改该实例参数」。
3. 关卡清单与世界拓扑并入关卡编辑器地图菜单。
4. 12 门禁重写：作废工具相关断言，新增层行为、功能绑定、ID 生成断言。

## 9. 明确不做

- 不做运行时脚本化内容：逻辑始终在项目侧代码。
- 不做编辑器内新增功能（功能声明是开发标准，不是编辑器功能）。
- 不做工作台画布的实例拖动（位置属关卡编辑器）。
- 不做内容「链接共享」：复用一律复制为新 ID。
