# V4 编辑器复审报告（基线 47fa03a）

范围：`src/` 全部 82 个 GDScript 与入口场景，约 27,500 行；`docs/` 仅用于理解契约。
方式：纯静态审查，未运行 Godot / 测试 / 基准。工作树审查时干净。
区分：**事实** = 控制流可直接证明；**时序** = 需特定竞态才触发；**待验证** = 依赖引擎行为。

发布判断：基线仍有数据完整性阻断项。首批修复（提交顺序、内容撤销、首次保存、
地图键歧义）已生效；剩余缺口集中在共用边界：以哪一版数据为准、操作拥有哪个目标、
写了什么、失败后如何继续。

## 1. 架构与数据流

| 链路 | 当前实现 | 应守住的边界 |
|---|---|---|
| 启动 | editor.tscn → app.gd → 清单校验/补码/资产扫描 → 三视图 | 游戏侧拥有资产与能力声明；编辑器消费同一份有修订号的声明视图 |
| 地图编辑 | 地图 JSON → MapStore → EditorCanvas.load_data → 瓦片层/实例/碰撞；多数编辑改活体，extract() 再拼整图；map_data 仅部分同步 | 工作状态要有版本；读取快照不得改手势与身份 |
| 内容编辑 | 声明 → FieldWidgets → 绑定 → 暂存/正式文件；已有内容即时写盘，新内容随提交 | 已展示值、正在编辑值、落盘值分开记录；共享内容用完整身份 |
| 保存/恢复/试玩 | UI 收集 → 临时 DocumentSession → DocumentCommit → 清单/内容/地图；草稿、历史、待完成日志各自维护；试玩重新取路径 | 从确认到执行用同一计划；收据要带路径与摘要；试玩消费提交结果 |
| 空间与引用 | 根格空间（出生点/碰撞/格边）+ 层局部变换 + 相机；画布/预览/导出各自取景与绘制 | 格拓扑、坐标换算、可见性、渲染策略各有单一归属 |

结构性观察：`UndoHistory` 兼管撤销、实例编解码与地图组装；`ProjectAudit` 与
`ReferenceIndex` 互相调用；“当前图是什么”“内容是否仍被引用”“格边是否存在”各有
多份实现；控制器通过 `app`/`cvs` 互读写私有字段。

## 3. P1 · 主流程、空间一致性与未报告失败

| 区域 | 事实与建议 |
|---|---|
| 打开/导入/切图 | on_open 在文件选择器之前就放弃改动并丢暂存；取消选图或载入失败时旧画布仍指向已丢暂存。外部导入首次代次检查在写盘之后。→ 选择/读取/确认/准备后再切换，写副作用前检查项目与文档身份 |
| 撤销/笔画/锁定 | undo() 遇开着的笔画会 stroke_cancel 而不回滚已涂格；中键/空格平移直接顶掉手势枚举；持续擦除读当前层，部分写入口绕过锁。→ 笔画结束即定格再撤销；手势切换先结算；锁定放进写入口 |
| 碰撞/出生点/吸管 | 进碰撞层只记旧模式，点击仍走摆放分支；首笔用夹到普通层的坐标、后续用根空间；出生点命中第一项比较光标与“光标所在格中心”；吸管对每层查同一格且忽略变换/隐藏，传出的 "paint" 被忽略 |
| 区域几何 | 幽灵用格号直接加，应用用 shift_cell()；三角/基向量列与奇偶行错位；缩放层上瓦片按本层格位移而实例按世界位移逆变换；目标层重映射未体现在幽灵 |
| 拓扑/主画布/取景 | odd-r 六边偶行邻接重复两项并漏左上/左下；三角轮廓走四方向邻居；斜基普通瓦片仍走原生预设；三角部分范围换算混用两种列；Home 在 lambda 内重绑 used 且混合格号与像素；预览 _fit/_origin 按正交宽高 |
| 批量替换瓦片 | 入口传空源资产枚举候选，collector 收到空值直接返回；修前置后 cur 重绑与双“替换”按钮仍在 |
| 记录控件/批量改值/提交失败 | 记录数组行工具接空 ctx；批量改值 commit 传空 Callable 且 cur_plan 重绑；数值控件一直比较建控件时的值；commit_fields 忽略写入结果 |
| 即时内容写入/绑定/步骤 | 字段写入用点击时才读的摘要做基线；步骤补丁按下标操作新结构；步骤刷新清空主表共用提交列表；cell: 选点走实体模式；时间失焦按两位小数重写 |
| 整图复制/引用重映射 | 预览有源图码、执行前剥码重发并重建计划；整图未读暂存；局部跨图时部分命中的列表重写整组 mapField；端口旧实例码与源图碰撞可覆盖第三图归属 |
| 图集/校验/导出 | 存在但解码失败的图集仍保留 ID 映射；图集缺失早返回留旧映射；零缩放通过校验；cellGraph 第二轮不验类型；批导出 await 后漏检项目身份 |
| 其他 | 尺寸弹窗把显式正交写成删除 gridProjection；图层操作全量重建且异步回调按下标；实例命中不按绘制顺序；poly/path 矩形命中；关系图空布局不清命中段；碰撞生成弹窗不监听源层；调色板缩略图缓存键不含图集修订；资产图鉴只列实体；资产保存回调不传播结果；资产重链逐条局部唯一；碰撞尺寸探针取首个形状且忽略节点变换；时间轴节拍起点非零时正反换算不可逆；FileDialog 打开后不释放 |

## 4. 四项遗留方案

### 4.1 内容与实例身份
1. 内容统一 `ContentKey(fn_id, cid)`；实例统一 `(map_code, instance_code)`；项目根与文档令牌承担作用域。
2. 先迁暂存、ID 预留、草稿、提交目标、删除检查，再接克隆、关系图、审计、检索。
3. 兼容旧草稿：现有行已带 fn_id/cid；更旧的裸 id 仅在唯一可推断时还原，歧义留待复核。
4. 绑定行与步骤行给稳定编辑令牌；外部换序后用展示基线重匹配，无法确认则放弃该控件写入权。

### 4.2 格边
1. 格边 = 根格空间两合法格共享的线段；`GridSpace.edge_between(a,b)` 给规范格对与真实共边段，点选/下拉/审计/连线共用。
2. 建议允许空格上的合法边：占用只筛候选，合法性由拓扑与定义域决定；`cell:` 有限格图以 cell_id 与显式邻接为准。
3. 整图复制时 `map: ""` 随副本解释；局部跨图复制钉源图；显式第三图保留；投影转换后在目标拓扑重验。
4. 先关误清：解析返回 ok/unset/missing/ambiguous/unreadable/invalid，先让现有审计按状态处理。

### 4.3 gridBasis / 渲染 / 取景
1. 先统一几何：GridSpace 提供变换/多边形/邻接/范围；MapViewData 构造名义与可见范围；以世界像素包围盒取景，命中取逆。
2. 再修坐标口径：三角列与基向量列区分；`hex+gridBasis` 三处口径不一致，暂列为不可编辑并保留原数据。
3. 原生 TileMapLayer 保留可对齐快路径；任意斜基与三角复用同一自绘后端，按可见块缓存、按实际变更层失效。
4. 导出区分“画面一致”与“布局示意”；前者统一切片变换/裁剪/遮挡/混合，两者都在分配前算预算。

### 4.4 持续文档会话与提交
1. 先把数据保护接到已有入口：共用文件状态与持久化接口，唯一同目录临时文件，create-only 用平台创建语义，替换/删除尽量贴近落盘复核基线。
2. 引入持续 DocumentSession：项目身份、文档令牌、工作修订、正式基线、暂存；初期仍从画布收集快照，同时抽出实例/碰撞/瓦片编解码。
3. 提交计划固定目标与字节：路径、操作类型、接受基线、冻结字节、预期摘要、依赖；执行器只按计划写并返回逐目标收据。
4. 分批接入口：常规保存/草稿/试玩 → 整图复制/改名/资产变更/跨图清理；日志区分已写/待写/可跳过/外部改变/日志损坏。

## 6. 实施顺序与待确认契约

1. 先防覆盖与误删（文件状态、创建基线、删除并集、歧义清理、碰撞整行）。
2. 收口身份与提交（ContentKey、共享暂存可达性、草稿发码恢复、文档令牌、冻结计划与日志）。
3. 恢复主制作流程（替换、批改、记录行、表单收集、锁层、笔画、碰撞、出生点、吸管）。
4. 统一空间并削减热路径成本（六边/三角、格边、区域计划、取景、分块渲染）。

待确认语义（本报告采用保守默认）：负坐标与范围外数据保留，仅显式有限域才拒绝域外格边；
内容按 (功能目录, ID) 寻址、复制发新身份、显式改绑才共享；已有内容即时保存、新内容随文档
提交，跨文件提交允许报告部分成功；通用 2D 的交付能力需如实描述，像素级一致与大地图容量
需运行证据。

## 8. 第二轮 P1 收口（§3 剩余行）

- 打开/切图：`on_open` 改为「选文件 → 读+校验 → 确认丢弃 → 载入」；外部导入的文档代次检查

- 其他：实例命中按画布绘制顺序（Below/YSort/Above + y-sort）；poly/path 用真实几何命中；
  关系图空布局清命中段；碰撞生成弹窗按层码监听源层；调色板缩略图缓存按图集修订失效；

  「上次真正写出的值」；`commit_fields` 传播写入结果；时间轴冲突集合按修订缓存。
- 测试：`test_grid_space` 增加三角列折算断言（位移/所在格/范围/边界）。全套 262 用例通过。
