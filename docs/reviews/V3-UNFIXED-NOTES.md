> `DocumentSession` / `DocumentCommit` 已落地。阅读当前缺口请以 [V6-COMPREHENSIVE-REVIEW.md](V6-COMPREHENSIVE-REVIEW.md) 为准，
> 本文仅保留当时的决策理由作为背景。

本文对应 [V3-EDITOR_AUDIT.md](V3-EDITOR_AUDIT.md) §7「尚未落地」的四项，说明为什么本轮没有修，

## 1. 内容/实例身份统一（§3.6 的剩余部分）

**已修的那一半**：图名与另一张图的地图码撞名时，`resolve_map` 现在会报告歧义
（`src/project/reference_index.gd`）。

**没修的一半**：`_staged` 只按裸内容 ID 索引（`src/ui/content_form.gd`），
而 `ContentStore.path_for()` 需要 `(功能ID, 内容ID)` 两段。改成 `"fn|cid"` 键要同步改：
暂存表本体、`rows_for`、`flush_one`、`restage_rows`、`drop_staged_for_current_doc`、
草稿载荷格式、`clone_plan` 的 `content_map`、删除入边检查。约 10 个读写点，
且**旧草稿只存了 cid**，需要向后兼容读取。

- 这是数据模型变更，不是局部缺陷。碰撞时谁覆盖谁，取决于「两个功能目录下文件同名」是否真的允许发生；
  这得先确认身份域，不能由实现方单方面决定。
- 一次改 10 个点、其中 3 个是持久化格式，在没有针对新语义的用例时，回归面大于收益。
  速度优先的前提下，这类改动应排在契约确定之后。

## 2. 格边三套判据（§3.7）

三处现状不同，是**设计选择还没做**，不是代码写错：

| 入口 | 当前判据 | 问题 |
|---|---|---|
| 画布点选 | 拓扑相邻即可 | 空格也能选 |
| 字段下拉 | 两侧都有瓦片 | 未保存的涂改看不到（读 `map_data.tiles`） |
| 项目自检 | 只查摆放物顶层字段 | 内容/步骤里的 `edge_ref` 不查 |

要统一，必须先回答两个问题：

1. **空格上的边算不算合法引用？**
2. **整图复制时「本图边」该指向原图还是副本？**

这两个答案会改变作者已经存下来的数据是否被判为「悬空」，也可能让自检开始大量报警。
猜错比留缺口更糟。

自检那半边更特殊：给内容/步骤字段补 `edge_ref`、`map_ref` 校验是**新增能力**，
不是修复既有判断，还带误报风险（跨图目标暂时读不到时该不该报）。这该单独做，
附一个「哪些情况不报」的规则表。

## 3. `gridBasis` 瓦片渲染与预览取景（§3.8 后半）

前半（显式正交落盘）已修。后半是**渲染架构问题**：

- 主画布非三角瓦片由 `TileMapLayer` 绘制，它只接受格尺寸 + 投影预设，
  **表达不了任意基向量**。要让 `gridBasis` 地图的瓦片也对位，只能在 `has_basis` 时
  切到逐格多边形绘制（像三角自绘那样）。这会改变主画布最热的绘制路径，
  大图的每帧成本要重新评估。
- 预览取景按 `w × tile_w`、`h × tile_h` 算（`src/ui/content_preview.gd`），
  等距/六边/斜基图会被裁。改成 `grid.map_bounds()` 会连带影响 `_fit`、`_origin`、
  `_zoom_at` 的整套坐标换算，必须看着画面调。

本轮只做静态审查，跑不了编辑器。这类「改完要肉眼确认对位」的渲染改动，盲改的返工概率很高。

## 4. 会话/计划职责收敛（§4）

`DocumentSession` 提交时临时创建、引用 UI 持有的暂存表；`UndoHistory` 兼管行↔节点转换；
控制器之间靠 `app.` 转发私有成员。

这是**结构性重构**，会碰到几乎所有 UI 控制器，属于「一次做对才划算、做一半更乱」的类型。
报告 §4 给的是顺序：先把局部缺陷收口、把行编码提取成共用转换、再接持续会话。
直接跳到第 2、3 步，等于同时改契约和实现。

## 一句话总结

已修的是**控制流错误、契约不一致、静默覆盖**——行为有唯一正确答案。

未修的是**语义待定、架构迁移、需要渲染验证**——三类的共同点是：
改错不会有报错，只会悄悄改变作者数据的意思。

## 建议的继续顺序

1. 预览取景改用 `map_bounds`（小、可验证、不动主绘制路径）。
2. 格边加一份「引用有效性」纯函数，让自检与下拉共用它（先只统一判据，不改候选语义）。
3. 暂存键改 `(fn, cid)`，并兼容旧草稿 —— 需要先确认身份域。
4. 会话/计划重构 —— 建议单独开一轮。

其中 1、2 可以直接做；3 需要先定身份域；4 建议独立成轮。
