# Karpathy 重构审计落实记录

对应 [原审计](EDITOR_KARPATHY_REFACTOR_AUDIT_2026-11-28.md)。本轮优先修会写错数据的行为，并从实际编辑路径中移除重复的复制、写入和状态维护。

| 审计项 | 落地结果 |
| --- | --- |
| A1 · 图层归属 | GUI 与 MCP 共用图层栈操作。MCP 更换首层前保存旧摆放物的有效层码；删除仍有隐式摆放物的图层会被拒绝。显式删除会按有效层清理摆放物，并保留解绑后的格图空间坐标。 |
| A2 · 实例定位 | 有实例码的对象按码定位；同时传下标时两者必须指向同一对象。仅无实例码的场景摆放物用下标定位。 |
| A3 · 内容规则 | 内容表单、演出及内容库共用声明校验。编辑旧内容时可逐项处理原有问题；地图暂存内容正式发布和 MCP 发布检查完整候选。画幅点和矩形按实际存储结构检查。 |
| B1 · MCP 批次 | 每张有改动的地图只在本批首次写入时复制。批次后续指令读到同一份工作数据；操作失败时既不改旧草稿，也不清掉重做。未改正文继续复用原草稿记录。 |
| B2 · 正式写入 | GUI 暂存提交与 MCP 发布都先冻结文本，用相同的写入与回执执行器，比对和落盘使用同一份字节。内容和清单各保留一个正式序列化入口。 |
| B3 · 项目校验 | 同一次项目检查中，地图绑定、内容上下文、屏幕和流程目标复用按功能与内容 ID 读取的结果。下次检查仍从当前文件或草稿读取。 |
| B4 · 画布与历史 | 地图快照、实例与节点的转换脱离撤销模块；载入、提取、区域搬动和历史共同使用。图层移动只改节点顺序和关联索引，撤销和重做应用位置差量。 |
| B5 · 演出编辑 | 每次编辑持有自己的原数据及摘要。段落调整在确认时按展示快照重新取编辑输入；时间轴拖拽和时间表单共用补丁入口。 |
| B6 · 预览 | GUI 和 MCP 共用时间取样规则。MCP 多帧只浅复制请求外壳，世界请求组装复用同一份暂存内容数组。 |

六万瓦片地图连续修改 60 次出生点：原操作循环四次为 **765–973 ms**，本轮为 **13–18 ms**。此对比包含首次复制，只测操作循环；未计入 HTTP、读取、最终校验、写盘或渲染。

Godot 4.7.2 的发布检查通过：169 个诊断目标零问题、125 个源码脚本编译成功、270 个单测、24 项刷怪试点检查和四套图形工作流全部通过。清单导出再减少一次复制后，以源码启动的真实 MCP HTTP 测试也通过，覆盖 11 个工具及发布、截图、试玩、冲突、地图编辑和仅大小写改名。

本轮保留现有文件格式和世界预览协议。世界请求在编码时仍可能重复包含暂存内容，并受 4 MiB 上限约束。长期工程索引、跨全部操作的画布数据迁移和文件批量搬迁不在本次实施范围。
