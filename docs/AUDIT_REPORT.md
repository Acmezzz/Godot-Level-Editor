## 1. 执行摘要

### 1.1 最重要的三句话

1. **有两个核心编辑操作现在就是坏的**：`Ctrl+C`→`Ctrl+V` 粘贴实体会调用 `EditorCanvas` 上不存在的方法 `cvs._fresh_inst_code()`；删层则完全没有删掉实体。两者都是静态证据链完整的确定性缺陷（C-01 / C-02），不是概率问题。
2. **有一条确定性数据损坏链**：`map_format.gd` 把 Godot 的变换位写成了 `12288`（应为 `16384`），且读回时用两位掩码，导致 8 种瓦片变换里 6 种「保存→重开」即被破坏（C-03）。复制地图不重发 `meta.code`，会制造两张同身份码的地图（C-04）。
3. **通用 2D 目标的瓶颈找对了位置**：分离架构成功把「玩法」外置（这部分几乎不受游戏类型限制），但把「空间」写死成了单一正方形网格 + 扁平对象列表。六边形、带高度的 2.5D、自由旋转、非网格空间、组合/路径/区域拼装，游戏侧补多少模块都补不了 —— 这些属于编辑器职责（任务三 §5、§6）。

**任务三：能否承担所有 2D 游戏（各种类型、各种视角）？**
**目前不能。** 结论必须基于用户给定的分离思想来读：

- **玩法 / 内容 / 规则维度（游戏侧职责）[OK] 覆盖面很广**：功能、条件、步骤、音频、时机全部由清单声明、游戏侧实现，编辑器只做绑定与填字段。这部分架构方向是对的，**游戏类型几乎不构成限制**，也不该由编辑器去补。
- **空间 / 视角维度（编辑器职责）[NG] 只覆盖 1.5 套投影**：`grid_space.gd` 只有 orthogonal / isometric；`manifest_validation.gd:433` 把 `gridProjection` 枚举**锁死**；`editor_canvas.gd:216` 强制 `Vector2i(tile_px, tile_px)` 正方形格。六边形、斜 45° 带高度、自由旋转、非网格连续空间、非正方形格做不了。
- **组装维度（编辑器职责）[NG] 只做到「摆单点 + 填字段 + 绑功能」**：`objects[]` 是扁平列表，没有父子嵌套、组合实例、连线、路径、区域、节点图。游戏侧能交付 prefab，编辑器却只把它当一个点摆下去 —— 这正是「可组装成品模块 → 真正拼装」的落空点。
- **结论**：瓶颈**不在游戏侧，在编辑器侧的 5 类通用原语**（可插拔坐标系、通用几何段、组合实例、已有数据的编辑控件、试玩双向闭环）。坐标映射 / 命中测试 / 框选 / 吸附 / 视图变换属于画布内核，无法下放给游戏侧（下放等于每个游戏重写编辑器，恰好推翻分离初衷）。
- **建议**：补**通用机制**，不补类型功能。R-01（GridProvider 接口 + 放宽枚举校验）、R-02（`paths[]`/`regions[]`/`links[]` 几何段）、R-03（组合实例）、R-04（补齐已有数据的控件，成本最低）、R-05（形状碰撞）为关键路径；R-06…R-11 为控件注册 / 校验规则 / 试玩双向协议 / 世界结构 / 时间轴 / 呈现插件配套。**明确反模式**：不要内置「塔防波次面板」「战棋网格面板」「对话树面板」。
- 含完整「视角能力矩阵」「15 类游戏类型能力矩阵」「做不了的具体部分与归属」「分阶段验收标准」。
- 详见 `AUDIT_2D_CAPABILITY.md`。

## 3. 审查方法与证据规范

1. **源码索引**：`Glob src/**/*.gd` 建立全量清单（58 个文件）；配合 `Grep` 全库检索符号定义/调用点、`Read` 逐文件精读关键路径。早期 `wc -l` 计 57 项、Python `rglob` 计 58 项，差异来自无尾换行文件，**以全量 Glob 清单 58 个为准**。
2. **证据链闭合**：每个缺陷都走「调用点 → 定义点 → 数据契约 → 后果」四段核对。例如 C-01 检索 `_fresh_inst_code` 全库仅 4 处命中，确认 `entity_factory.gd:88` 唯一定义、`editor_canvas.gd:845-850` 未委托、`cvs` 为无类型变量 → 判定为运行时错误而非编译期错误。
3. **注释不作为证据**：所有「能力存在」的判断都回到实现。典型反例：`project_audit.gd` 头注释声称查内容码漂移，`audit():13-29` 实际只有 3 步 → 判为虚报。
4. **跨文件一致性**：文档 ↔ 代码、生产端 ↔ 校验端（C-05）、写盘端 ↔ 读盘端（C-03）、异步调用方 ↔ 被委托方（C-07）均做双向核对。
5. **外部事实核验**：Godot 4 `TileSetAtlasSource` 变换常量（4096 / 8192 / **16384**）与 GDScript 字符串换行规则，均通过官方文档交叉确认，未凭记忆下结论。
6. **不夸大结论**：静态能确定的写「已证实」，需要运行才能定的（如 C-11 的 rename 覆盖语义、C-07 的竞态窗口表现）明确标注「需运行复现」，并单列于 §5。

## 7. 一句话交付判断

**不建议以当前状态进入内容生产或对外交付**：先完成阶段 0（7 个 P0 + 高优先级 P1 + 文档硬错误修订 + 一次 Godot 运行验证），再按 R-01…R-05 扩展编辑器侧的通用空间与组装原语。分离架构的方向是对的、初版完成度也高，值得在这个地基上继续做 —— 但「能承担所有 2D 游戏、各种类型和视角」目前还是目标，不是现状。
