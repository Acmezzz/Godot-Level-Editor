# 执行文档：图层开放化 + 脚本演出 + UI 边界

> 2026-11-20 定稿（v2：去 BG 化 + 运行时层开关 + 事件区升级）。
> 前置已完成：音频声明池（commit 0235526）。
> 约定：零兼容——涉及数据契约的改动不做旧数据迁移；编辑器不解释玩法语义；
> 不跑门禁/测试（既定约定），每步 `--check-only` 全量过。

## 1. 图层开放化（画布重构）

### 1.1 模型（定稿口径，v2）

- **层 = 纯 z 槽，只管画画**：遮挡关系是层的唯一语义；资产只管摆放，层管放在哪一层。
  **执行层面与层无关**——不同层的实体照常交互、不需要任何特殊代码；游戏侧逻辑管线
  不读图层，层只进渲染管线。
- **没有 BG 概念**：不设固定背景层——差分视图（多套背景来回切）、前景背景全靠用户
  自建普通层。新建图模板 = `[资产层, FL]` 两层，纯命名约定、无语义差异，可改名可删。
- **混合层**：一层可同时有瓦片和实体（含「背景实体」）；事件区也可以专门建一层摆放。
- **运行时层开关**：层数据带 `visible`（运行时初始可见，默认 true，层管理里可改）；
  游戏侧声明「开关图层显示」类功能，配合新 choice source `layer:`（列本图层，值=层码）
  在运行时切层显隐——差分背景、BOSS 转阶段换景都走这条路。
- **碰撞退出层栈**：碰撞与 z 序无关（游戏内不可见），保持独立元层——固定一个碰撞网格，
  编辑器红叠加永远画在最上面，类型/形状下拉照旧。

### 1.2 数据契约（变更，零兼容）

- 地图 JSON：`meta.layers = [{id, name, visible}]`，数组序 = 栈序（底→顶）；层 id = 4 位码，
  出生即定、改名不破引用；新建图模板 = `[资产层, FL]`。
- 瓦片按层存：`tiles[层id] = [5元组...]`（替代固定 terrain/decor/collision 三键）。
- 实体加层：`entities[].layer = 层id`（缺省 = 最底层）。
- **清单 `layers[]` 退役**：图层逐图声明；`SUPPORTED_TILE_LAYERS` 白名单删除；
  清单校验的图层检查删除。

### 1.3 行为规则（编辑器与游戏侧同一套）

- **栈序即绘制序**（底→顶）；同层内瓦片先画、实体后画（实体立于同层瓦片之上）。
- **绘制语义跟资产走**：左键行为由当前选中的资产种类决定（瓦片=按格拖涂、实体类型=点放），
  落点 = 层选择器的当前层。
- **右键擦除**：作用于当前层——命中实体删实体，否则擦瓦片。
- **实体命中跨层**：从顶层向下取第一个命中。
- **删层 = 删内容**：该层瓦片与实体一并删除（整图快照撤销可回）；实体不自动搬家。
- **跨图粘贴层重映射**：按层名匹配；匹配不上落**最底层**并黄字提示。
- 吸管/自动边缘等 terrain 特化逻辑一律改「当前层」自审（不再认 id）。
- **层只进渲染管线**：跨层实体交互零特殊处理（上面规则的推论，单列提醒游戏侧）。
- **运行时层开关**：`layer:` 来源列当前图层（值=层码，同 `entity_inst:` 模式），供
  「开关图层显示」类功能选层；层数据 `visible` = 运行时初始可见态。

### 1.4 编辑器改动清单

| 位置 | 改动 |
|---|---|
| editor_canvas | 3 固定节点 → 按 meta.layers 栈序创建 N 组节点（TileMapLayer + 实体容器）；碰撞网格与红叠加独立于栈 |
| tool_ops / canvas_input | 涂刷/擦除/盖章改「当前层」寻址；语义跟资产走 |
| selection_ops | 实体带 layer；复制/粘贴/区域操作携带并重映射层 |
| editor_layout | 左栏层选择器 + 层管理（新建[默认插到栈顶之下]/改名/删除/上移下移）；调色板与层解耦，改「瓦片/实体」页签自选 |
| canvas_draw / content_preview | 按栈序绘制/预览 |
| undo_history | 整图快照天然覆盖层操作（无改动，验证即可） |
| map_store / map_data_validation | 读写按新契约；校验按 meta.layers（层引用存在性） |
| content_editor | `_resolve_options` 新增 `layer:` 来源（列当前图层，值=层码，显示=层名） |

### 1.5 游戏侧对应

按 `meta.layers` 建渲染容器（栈序 = z 序）：每层一个瓦片容器 + 实体节点，同层瓦片先
实体后；碰撞读碰撞网格。约 30 行，同 CODES.md 映射模式。

### 1.6 验收口径（用户自验）

1. 新图默认「资产层 / FL」两层（可改名可删）；建新层、调层序后遮挡随栈序变化；
2. 同层放瓦片+实体，实体在瓦片上；顶层（FL 或任何上层）能盖住下层实体；
3. 删层内容消失、撤销可回；跨图粘贴层名匹配；碰撞红叠加永远可见可画。

### 1.7 事件区（trigger_zone 概念升级，近零改动）

- 「有些东西不在具体实例上」= 已有的 trigger_zone：透明矩形、props 只有 w/h，摆哪层都行
  （混合层天然支持「专门建一层摆事件区」）。
- **触碰触发 vs 条件触发都是时机问题，归游戏侧解释**：条件触发 = 绑定的功能声明引用
  条件库（如击杀计数达成即触发），无需碰撞——链路已存在，编辑器无新机制。
- 编辑器改动仅显示口径：内置种类显示名「触发区」→「事件区」（kind 名与数据不动）。

## 2. 脚本演出

### 2.1 模型

- 演出 = 一个功能（挂实例、声明链引用条件库做触发）+ 内容里的**步骤数组**。
- 清单顶层新增**步骤池 `steps`**：与 functions 同形（`{id, name, fields}`），游戏侧声明
  步骤功能（move_to / play_anim / wait / show_dialogue / camera_pan …）。
- 演出内容文件：`steps: [{step: <步骤码>, fields: {<字段码>: 值}}]`；步骤字段码与功能/
  条件字段**共用一个码空间**（ensure_codes 链延伸到步骤池，跨池查重同规则）。

### 2.2 编辑器

- 功能声明加可选键 `"steps": true` 标记演出功能；内容表单对带标记的绑定渲染步骤只读
  摘要 + 「编辑演出」按钮 → **子面板**：步骤列表（增删/拖序/复制步）+ 当前步参数表单
  （复用 field widgets 与 choice source——步骤里指实例=entity_inst、选音频=audio:）。
- 内容复制：steps 随内容复制；步骤码引用清单声明、跨内容共享，无需重映射；步骤里的
  实例引用随内容原样带过（与现有内容引用字段同一行为）。
- 校验：step 引用必须已声明；步骤字段码同空间查重。
- CODES.md 增「## 步骤」段。

### 2.3 游戏侧

运行时按 steps 顺序解释执行；触发条件走既有条件库链路。

## 3. UI/HUD/菜单 —— 分工边界（无编辑器改动）

- 编辑器管：触发点（实体功能绑定）、UI 消费的数据（货架商品=content 条目、任务目标=
  条件参数）、UI 里的引用（entity_inst / map / audio:）——现有机制已全部覆盖，无改动项。
- 游戏侧管：HUD 布局、菜单树结构与导航、样式动效、对话框呈现。
- 菜单结构**不**进编辑器（改菜单的人必然同时改 UI 代码，拆两处互相牵制）。

## 4. 实施顺序与提交切分

1. **脚本演出**（独立、小）：steps 池 + 声明标记 + 校验 + CODES + 演出子面板 → 一个 commit。
2. **图层开放化**（大、动契约）：画布层栈重构 + 数据契约（含 `layer:` 来源、层 `visible`、
   事件区显示名）→ 左栏 UI → 粘贴重映射 → 2–3 个 commit。
3. 每步 `--check-only` 全量过；**先演出后图层**（演出不动画布，风险小先行）。
